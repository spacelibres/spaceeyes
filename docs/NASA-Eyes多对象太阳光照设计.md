# NASA Eyes 多对象太阳光照设计（A33 决策稿）

状态：设计决策稿，未实现、未验收。日期：2026-11-01。
上位依据：[第一版规划与验收](第一版规划与验收.md)、[NASA-Eyes 全局逐项复审（2026-11-01）](NASA-Eyes全局逐项复审-2026-11-01.md)、[NASA-Eyes 光照与全屏操作设计](NASA-Eyes光照与全屏操作设计.md)。
本稿只回答“多对象同屏时，每个天体如何得到指向真实太阳的光照方向”，不实现代码、不改变资源、不宣布 A33 完成。

## 1. 问题与证据

复审 A33 定位 `core/src/renderer.rs` 的 `update_illumination`：场景只有一盏 `SolarDirectionalLight`，方向由 `DisplaySettings.origin_km` 指向 ICRF 原点；当显示原点为零时直接 `return`，保留上一方向。结果是：

- 单一平行光只能表达一个方向，无法同时照亮地球、金星、火星、木星等不同位置的天体；
- 显示原点变化时，光方向跟随“当前原点”，不是每个对象各自指向太阳；
- 太阳总览 origin=0 时不更新，方向可能停留在上一场景；
- WebGL2 的 Bevy `MAX_DIRECTIONAL_LIGHTS=1`，不能靠“每对象一盏 `DirectionalLight`”解决；
- `shadow_maps_enabled=false` 仍未完成阴影，不能把本设计等同于阴影完成。

已有补光设计（natural/shadow/flood 的 `PointLight`）是相机辅助光，不是太阳方向；本设计不改变补光语义，也不改变太阳自发光、银河 IBL、曝光或背景亮度。

## 2. 需求

1. **方向正确**：每个受光天体的光照方向，必须由该对象在显示空间中的位置指向同一科学时刻的太阳位置；对象旋转/自转不改变“指向太阳”的世界方向。
2. **同屏多对象**：地球、火星、木星等同时可见时，各自得到不同方向；不能只保证当前焦点对象正确。
3. **同一时刻**：使用核心当前显示的同一 `DisplaySettings`、同一太阳位置和局部原点；不得在 TS 或每帧重新推导第二套状态。
4. **保留既有能力**：natural/shadow/flood 补光、太阳程序化外观、银河/星场、行星环、航天器 PBR、标签/轨迹、显示比例和科学语义不退化。
5. **WebGL2 优先**：浏览器 WASM 是主路径；不能依赖“多方向光”或原生才有的灯数上限。
6. **画质不降级**：不得用降低纹理、减少对象、缩小轨迹或提高全局环境光来掩盖方向错误。
7. **可验证**：提供同对象、同时间、同视角的 NASA 成对截图；提供方向计算单测和 GPU 场景；无法测量项明确列缺。

## 3. 方案比较

| 方案 | 做法 | 优点 | 致命问题 | 结论 |
|---|---|---|---|---|
| A 当前单方向光 | 全场景一盏，方向随显示原点 | 已存在、便宜 | 多对象方向错误；origin=0 保留旧方向 | 淘汰 |
| B 太阳位置点光 | 在太阳显示位置放 `PointLight` | 方向逐对象自然正确 | 显示压缩后逆平方衰减巨大；亮度/范围难统一；多灯与阴影成本；不能表达“无限远太阳” | 不作为主方案；可作局部近景补光试验 |
| C1 `ExtendedMaterial<StandardMaterial, M>` | 在扩展材质中增加“对象空间太阳方向”uniform，并尽量复用 Bevy 的 PBR WGSL，替换/补充太阳方向 | 尽量保留标准 PBR 通道；每对象 uniform；方向在 Rust/Bevy 计算 | 必须验证 0.19.1/WebGL2 下能否在不复制整段 PBR 的前提下覆盖方向光贡献；若不能，C1 实际退化为 C2 | **推荐先做技术验证** |
| C2 独立自定义 PBR 材质 | 自己写完整 PBR + 太阳方向 | 完全可控 | 重实现 normal/specular/night/cloud/atmosphere/环/阴影，回归面大；与现有材质分叉 | 仅当 C1 被证明不可行时的后备，不先做 |
| D 多相机/图层各一盏方向光 | 每个对象/图层单独 view + 灯 | 每 view 可有一盏 | 多 view、过绘、合成、拾取、性能与维护复杂度高；不是 NASA 语义 | 淘汰 |
| E 顶点/法线烘焙 | 把太阳方向烘进法线/顶点色 | 无每帧 uniform | 对象运动/时间变化即错误；多对象仍不对 | 淘汰 |

## 4. 推荐方向（先验证，不直接实现）

采用 **C1：每对象一个“太阳方向”渲染采样，优先通过 `ExtendedMaterial<StandardMaterial, M>` 注入**；能否复用 Bevy PBR WGSL 是该方案成立的前提，不能预设。

### 4.1 数据流

1. 核心（Rust/Bevy）已拥有 f64 科学位置、显示原点和太阳位置；TS 不参与。
2. 在渲染同步阶段（与对象变换同一批）计算：
   - 对象显示空间中心 `p_obj`（f64 减原点后转 f32，沿用现有精度路径）；
   - 太阳显示空间位置 `p_sun`（同一原点/同一时刻）；
   - 世界方向 `d_world = normalize(p_sun - p_obj)`；
   - 对象空间方向 `d_obj = inverse(object_world_rotation) * d_world`。
3. 将 `d_obj` 写入该对象材质的 `SolarLightSample` uniform（`Vec3` + 有效性标记），而不是改全局灯。
4. 材质在 PBR 光照中使用 `d_obj` 作为太阳方向；补光仍由现有 `PointLight` 处理；太阳自身保持 unlit/自发光。
5. 方向变化小于阈值（例如 1e-5）时不重写材质；对象切换/原点重基/太阳位置变化必须重算。

### 4.2 为什么是对象空间

- 天体自转/姿态变化时，世界方向不变，但对象空间方向变化；对象空间 uniform 让材质无需知道世界变换。
- 避免每帧在 shader 里做世界矩阵求逆；Rust/Bevy 侧每对象一次，成本可控。
- 与现有“局部原点 + f32”显示路径一致，不在 shader 里直接使用巨大绝对坐标。

### 4.3 与全局方向光的关系

- 迁移期保留 `SolarDirectionalLight` 作为**未迁移对象/阴影实验**的回退，但迁移后的行星材质不得同时接受全局方向光和逐对象方向，避免双倍照明。
- 第一阶段把全局方向光对“已迁移行星”的贡献关掉（通过材质不读取全局方向光，或将全局灯强度设为 0 并用逐对象采样）；不能简单把全局灯调暗来“看起来对”。
- 环、航天器、太阳翼等自定义着色器是否读取同一 `SolarLightSample`，分阶段统一；未迁移对象必须显式标记回退，不得静默混用两种方向。

## 5. 关键技术验证（编码前必须做）

在独立 spike 中回答，不以推测代替：

1. Bevy 0.19.1 + WebGL2 下，`ExtendedMaterial` + `MaterialExtension` 能否在标准 PBR 光照阶段替换/覆盖方向光方向，而不复制整套 PBR？若必须复制完整 PBR，则按 C2 重新评估，不冒充 C1。
2. 扩展材质的 bind group 是否每对象独立（每对象一个 material handle），而不是共享材质导致 uniform 串写？
3. 预pass/阴影/透明排序是否仍正确；`enable_prepass`/`enable_shadows` 如何设置？
4. 环、太阳翼、模型 PBR 的现有自定义 shader 是否可复用同一方向采样；不能复用时是否至少保持原语义并显式标记？
5. 原生与 WebGL 的光照数值差异是否在可接受范围；不能用原生测试替代浏览器。
6. 每对象材质数量/显存/绘制批次增量；若不可接受，再评估共享材质 + 实例 uniform/存储缓冲，而不是退回全局灯。

**验证未通过前不进入产品实现。**

## 6. 分阶段计划（每阶段单独提交）

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| S0 设计/spike | 本稿 + 独立分支最小材质验证；不改产品场景 | C1 可行性结论；记录 Bevy 版本、WebGL 限制、截图/日志 |
| S1 方向采样 | 在 Rust/Bevy 增加每对象太阳方向采样与单测；不接材质 | 原点重基、对象旋转、太阳位置变化单测通过 |
| S2 行星材质 | 迁移球面行星到逐对象方向；保留补光/太阳外观 | 地球+火星同屏方向正确；无方向光超限警告 |
| S3 环/航天器/自定义 | 按实际 shader 接入或明确回退 | 环、太阳翼、模型 PBR 不退化；回退可见 |
| S4 GPU/NASA 对照 | 同对象同时间同视角成对截图；性能/画质同条件 | 记录证据；未测项不勾选 |

阴影（`shadow_maps_enabled`）不在本设计承诺内；若要做，必须另立批次并单独验收，不能因方向正确就宣称阴影完成。

## 7. 验收标准

### 7.1 计算/单测

- 原点为 0、非 0、极大/极小显示尺度下，`d_world` 指向太阳且单位化；
- 对象绕任意轴旋转后，`d_obj` 经对象旋转回世界仍等于 `d_world`；
- 太阳与对象重合/缺失时，返回明确 `unavailable`，不回退到旧方向；
- 原点重基不产生可见跳变；方向阈值不造成迟滞错误。

### 7.2 GPU/页面

- 地球、火星、木星同屏：各自明暗界线朝向太阳，不是同一方向；
- 地球昼夜、金星、土星环、ISS/航天器 PBR 与 natural/shadow/flood 补光不退化；
- 太阳自身不被照亮，太阳外观/日珥/银河/星场不变；
- WebGL 控制台无 `MAX_DIRECTIONAL_LIGHTS` 超限；原生与浏览器均验证；
- 同对象、同时间、同视角的 NASA 成对截图；记录环境、版本、SHA；
- 性能在同功能同画质下测量；不以平均 FPS 或单场景替代。

### 7.3 明确不宣称

- 不宣称完整 NASA 光照模型、物理照度等价、阴影/大气/云层完成；
- 不宣称所有天体/所有材质通道完成；
- 不把本设计稿当作实现或验收。

## 8. 风险与开放问题

1. `MaterialExtension` 在 0.19.1/WebGL2 的光照覆盖能力未验证；若不能覆盖，C2 的回归成本高，需要用户确认是否接受范围收窄。
2. 每对象材质会增加资源句柄/绘制批次；需测量显存与帧时，不能以“对象少”假设。
3. 环/太阳翼/模型 shader 的太阳方向来源不统一，可能出现“行星正确、环错误”的半迁移状态；必须显式标记并在 S3 收口。
4. 太阳在场景中不可见或被遮挡时，方向仍应由科学位置决定；不能用屏幕位置替代。
5. 补光 natural/shadow/flood 与太阳方向是两套语义，不能把补光当太阳光，也不能为让暗面可见而提高太阳强度。
6. 阴影是独立能力，当前 `shadow_maps_enabled=false`；本设计不授权开启全局阴影或降低画质。

## 9. 结论与下一步

- **推荐**：先做 C1 的独立技术 spike，验证 `MaterialExtension` 的可行性；通过后再按 S1–S4 迁移。
- **不推荐**：继续用单方向光、每对象一盏方向光、太阳点光或顶点烘焙来“看起来正确”。
- **下一步**：本稿评审通过后，只创建 spike 计划与失败用例，不直接改生产渲染路径；spike 结论再决定 C1/C2。
