# 0.0.101 进入工作区前的真实渲染就绪

网页0.0.101、核心0.0.69，SDK0.0.57保持。修复start_renderer返回后立即报告ready，实际首次WebGL管线仍在编译，用户已经看到场景却无法操作的问题。

冷启动基线复现了11116ms、4168ms和3630ms主线程长任务；一次完整鼠标手势等待17233ms。CPU采样主要位于WebGL getProgramParameter，符合同步查询着色器链接状态的阻塞路径。源证据是本机实际WASM、浏览器CPU采样和锁定Bevy0.19.1 PipelineCache源码；MDN也说明[编译状态同步查询会破坏流水线](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。

核心在真实Render子应用完成一帧后报告渲染管线的pending/failed及连续完成帧。ShaderNotLoaded/ImportNotYetAvailable属于继续等待；确定的编译错误报失败。WebGL不支持的闲置compute管线不属于显示就绪条件：第一次实机验收发现等待全局管线会永久停在一条compute任务，因此未采用该实现。宿主保留既有加载页，待初始太阳系显示资源完成或明确失败、渲染管线连续就绪、资源准备完成后又完成三帧，才报告ready并允许进入；取消会释放等待的动画帧，无固定秒数进度模拟。

实际Intel Arc B390/ANGLE D3D11两轮浏览器验证：第一轮约20.1秒进入，独立新浏览器配置约37.1秒进入。两轮各12组进入后立即拖动/滚轮，观察窗口均无进入后的>50ms主线程长任务；事件最大排队分别20.8/21.9ms，完整多事件手势最大149/126ms。额外四组在两个真实动画帧后检查相机，全部位姿改变。新浏览器轮次仍有6896ms、3857ms等编译长任务，全部处于加载阶段。本版修复就绪判定与输入开放时机，冷启动编译仍同步；不同浏览器/驱动缓存状态不能用来宣称编译耗时已优化。

完整本地Rust/TS/WASM/Clippy/发布构建、资源检查和168项原生渲染通过，含141项网页、78项工作区集成。新增测试覆盖实际完成帧、未完成GPU状态、资源晚到、失败和取消；集成测试禁止数据完成时提前报告active/ready。实际CPU分阶段、显示间隔、JS堆和GPU型号见metrics.json；GPU执行时间、显存与进程RSS未测，JS堆样本不代表全部WASM/Worker/GPU内存。画质比例保持1，未改变对象、轨迹、动画或资源精度。此前ISS极近景几何发布延迟仍属独立未完成项。
