# 0.0.95 高速拖尾验证

版本：网页0.0.95、SDK0.0.53、核心0.0.67。目标是修复加速时整组拖尾计算失去进展，并保持科学时刻、原始时长、对象数量和显示精度。它不是NASA全项对齐的完成声明。

## 发现与修正

NASA本地参考：`solarsystem/eyes/src/engine/components/TrailComponent.js` 的 `_updatePoints` 保留历史点并补齐移动区间。原实现存在64任务所有权淘汰、每帧仅安排一个对象、过期后才补算、历史覆盖探测替换正式高精度缓存、相机状态落后100毫秒等相互影响的问题。修正保留真实数据和源缺口，不用直线猜测缺失头部。

实机ISS近景中主线程渲染占用较高，单靠主线程分帧不能稳定完成整组采样，因此将原生科学源轨迹交给一个纯计算Worker。相同公式、快照及Float64结果有一致性回归。主线程仍拥有时间、相机、源版本、SDK发布和生命周期；历史求值路径及Worker失败回退保留。计算队列放在platform，网页原入口仅兼容导出，科学模块不反向依赖网页宿主。

Worker不请求网络或初始化WASM。源只在变化时增量复制，未变化的太阳状态不因每帧时间变化制造源版本。主线程只在帧预算内转换/发布已完成结果，过期、不同阶段和旧所有者结果拒绝发布。科学前后缓冲独立分配，可见部分的原误差与点预算不变；输入容量为单路径4096点、每会话49152点。

## 浏览器与真实显卡

使用项目现有Playwright CLI的独立无头Chrome会话；设备为ANGLE/Intel Arc B390/D3D11，不是软件渲染。基础复现时刻为`846972583.005967`，FOV45，shadow光照，labels/orbits/trails/moons/craft均开启。ISS使用nearby/orbit，地球使用system/orbit。

测试透传记录应用自身WasmCore轨迹发布，按RAF检查每个已发布目标的当前时刻是否在真实采样首尾之间，并检查可见窗口的首尾覆盖。探针不修改科学数据或结果；每页强制新文档加载，避免仅改变hash继续运行旧构建。统计保留1200帧上限。`metrics.json`记录每次末5秒的样本数、目标数、头部未覆盖数及真实源不足的窗口。

ISS 1×、通过实际时间轴键盘操作从1×调整到+3600×、直接-3600×，稳态末5秒所记录目标的当前头部未覆盖数为0。暂停时刻不变，恢复后按原方向推进。单个Worker实际加载并运行，相关截图在本目录。部分长窗口的历史尾部不完整，不能把头部通过解读为所有历史都已补齐。

时序是含轻量探针的现场记录，不是对照完全相同画面的性能A/B试验。核心CPU与显示间隔分开保存，target_fps为已批准的30fps调度，resolution_scale保持1；间隔存在长帧，不承诺恒定30/60fps。当前诊断未提供GPU时间，显存和Worker堆内存未单独测量，页面heap估计不能代表整个进程或Worker内存。

## 尚未解决

实际加速条压力测试到达-36000×时，仍观察到部分头部超出缓存覆盖，后续版本继续处理。不能用此版本宣称所有高倍率已修复。

初始时刻记录了Cluster II FM5/FM7/FM8、DSCOVR、ESCAPADE Blue/Gold、GRIFEX、Roman、TESS的502请求；完整控制台另存，不将已有数据源错误说成通过或着色器失败。长历史、跨任务阶段和不兼容分段不能以推测连接补全。远端CI状态提交后另用gh核验。
