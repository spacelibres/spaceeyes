# 0.0.96 高速拖尾恢复与计算调度验证

版本：网页0.0.96、SDK0.0.54，核心保持0.0.67。对照本地 NASA Eyes `TrailComponent` 的持续历史更新语义；不是 NASA 全功能一致的声明。

## 修复范围

- 一个工作区使用固定、按对象稳定分片的1至4个纯几何计算Worker。科学求值、Float64、源版本、生命周期及受控发布不变；网络与Bevy仍由原有职责管理。
- 连续拼接的完整溯源曾被重复塞进每帧ObjectState.source，超过2048字节后有效卫星被状态契约拒绝。实测NOAA21第6次跨段达到2194字节；改为有界摘要后8次实测保持608字节，完整分段档案仍通过provenance读取。12次拼接回归验证完整档案仍超过2048字节且所有发布合法。
- 预取依真实过期时间排序，冷却依据真实单分段跨度；切换播放/倍率/方向/场景会取消旧预取，过期结果不能修改源或恢复旧冷却。实际源连续性、控制器、父体、参数、重叠节点仍严格验证。
- 实测CYGNSS2的32774秒分段请求耗时0.23～0.80秒，高倍率下原4个网络名额无法覆盖全组需求。网页改为最多32个源请求并行等待网络，但正文读取与哈希仍最多4个，保持原响应缓冲并发；单响应16MiB、源100万记录及每源64段上限不变。并发不是减少精度的替代方案，实际堆内存另行测量。`SolarSystemData`默认仍为4，显式配置只接受1至32。
- 次要源最多4个主动请求，获得名额后才读当前仿真时间，不将数十个旧时间请求堆在网络队列。曾成功显示的源遇临时失败按已有1秒节奏恢复；从未可用的源不新增轮询。
- 已显示航天器的轨迹意图跨临时源不可用保留，源恢复后能重新发布；恢复其它模型的帧仍按剩余预算推进轨迹任务。Worker等待状态立即结束当前计算量子，不再忙转4096次。
- 航天器真实采样缓冲的有效时间按完整已采样窗口计算，不套用天然解析轨道的半周期便捷范围；已有部分历史保留明确缺口。没有缩短拖尾、隐藏对象、取消动画或改变资源精度。
- 0.0.95远端CI在慢运行器的密集场景测试失败。该功能测试原本混用手动RAF时间与真实工作时钟；现在注入同一个有限、单调的测试工作时钟，生产仍用performance.now。保留1500帧、至少40条真实目录轨迹及容量断言；111体协议测试明确产生定期新请求，保留原覆盖断言。

## 验证与边界

最终本地检查、GPU实测及未完成项见同目录checks.log、metrics.json。GPU时间与显存没有计时/计量入口，不能用CPU渲染阶段时间代替。源502、真实历史不足与计算过期分别记录；不能把“头部有覆盖”表述为所有历史完整。


### 本版实机结果

固定起始时刻846972583.005967、FOV45、shadow、全部图层开启，实际Intel Arc B390硬件渲染。地球system模式20×末5秒67个已发布航天器头部均有覆盖；ISS近景从UI拖动至+3600×，末5秒最多1个短暂落后、最终0个；随后UI倒放-3600×末5秒均0个，暂停两次读取时刻相同，恢复后向负时间推进。使用4个实际Worker，resolution_scale为1。ISS正放CPU p95约20.6ms、显示间隔p95约35.4ms，倒放21.4/36.1ms；初始化等阶段仍存在长帧，不宣称恒定30/60fps。

每秒推进10小时（+36000×）仍未通过：67个已发布目标末5秒最多43个头部超出旧采样、最终38个。部分长历史（ACE、IMAP、JWST、SOHO、SOLAR-1、WIND等）仍真实部分覆盖；不能把当前头部有覆盖当作全历史完整。进一步源请求记录显示服务端每次重复读取NASA索引，600～1400ms往返超过部分分段的播放寿命，下一版独立处理精确字节缓存与共享请求。本版不宣称高速问题全部修好。

CDP采样记录于metrics.json：主线程与4个Worker的Runtime堆分别列出，未强制GC；只是JS堆/ArrayBuffer指标，不是RSS、显存或严格进程内存上界。GPU耗时与显存未测。源端502仍可见，详见console.txt，不是干净控制台。0.0.95远端CI已确认失败；本版提交后另行通过gh检查结果。
