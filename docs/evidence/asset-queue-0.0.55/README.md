# 资源队列与完整场景恢复验证（网页0.0.55）

本批是“资源与显示闭环”的内部里程碑，不是整个闭环或NASA视觉对齐完成。

## 来源与影响边界

NASA本地恢复代码 `solarsystem/eyes/src/engine/core/Downloader.js:25–39` 取消排队下载时会将其移出队列，再推进下载调度。仅参考这个生命周期原则，没有复制实现。

本项目 `EyesAssetService` 原先仅在调用者共享层及时拒绝取消；内层并发队列仍保留被取消的等待者，必须等慢下载释放后才逐个清理。两条慢下载与64条已取消等待会让新场景误报队列已满。测试已在修改前复现明确错误 `Asset request queue budget`，修复后通过。

修复仅改变服务器资产队列准入/取消及槽位交接。并发2、等待上限64、同资源订阅共享、校验、缓存、模型转换、科学时间和SDK保持原契约。取消等待者同步移除，尚未拥有槽位的取消不释放槽位；完成时先将所有权交给下个等待者，避免插队和超额并发。

## 自动验证

新增实际服务测试覆盖：两条慢下载不结束时连续取消64个等待后，新场景仍能排队；取消项不发起上游下载；FIFO槽位移交；活动下载错误仍向调用者返回。原有共享订阅一方取消不影响另一方的测试保留。

全量 `check-core.ps1 -Renderer -ReleaseWasm -Workspace -NativeCamera -Samples validation/.cache -JunoAssets -SolarAssets` 通过：142平台/校验、16真实WASM、2真实DYN、52网页、50宿主集成、111原生渲染，以及Clippy、TS、发布WASM、生产构建和离线资源检查。

首次全检暴露新测试错误地假设缓存异步读取顺序等于调用顺序，测试改为按实际完成事件等待；修改后重新执行完整检查通过。不是放宽超时或跳过测试。

独立审查没有发现当前差异的明确正确性或回归问题。
