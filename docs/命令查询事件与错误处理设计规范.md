# SPACEEYES 命令、查询、事件与错误处理设计规范

版本：0.0.0｜状态：第10阶段设计草案｜日期：2026-10-27
范围：仅Markdown架构设计；不编写Rust代码、不创建.proto文件、不运行测试。
依据：第08阶段核心对象模型、第09阶段Proto消息字段设计、已批准ADR-001至ADR-009。

## 1. 目标与不变量
定义Core Protocol的Command、Query、Response、Event、Error、事务、权限和幂等语义。Engine是唯一公开写命令入口；Scene/Time/Resources各自维护领域不变量；Simulation仅提出经验证的状态更新。所有公开结构化交换使用Protobuf，Rust内部领域模型与Proto生成类型分离。

## 2. Command生命周期
候选状态：RECEIVED、VALIDATING、ACCEPTED、EXECUTING、COMPLETED、REJECTED、CANCELLED、FAILED。
- RECEIVED不代表授权或有效。
- ACCEPTED只表示进入受控执行流程，不代表最终状态改变。
- COMPLETED必须包含最终结果、提交修订号及可关联事件。
- REJECTED表示未执行的校验或授权拒绝。
- FAILED表示执行阶段失败；必须说明是否发生任何外部副作用。
- CANCELLED表示取消完成或任务结果不再可提交；取消请求本身不保证外部副作用撤销。
- 不允许一个请求既被标记为最终成功又返回不可恢复错误。

## 3. CommandEnvelope
沿用第09阶段设计的RequestContext及oneof payload。
RequestContext至少包含request_id、session_id、protocol_version、expected_scene_revision（可选）、time_generation（可选）、correlation_id和causation_id。
外部命令进入Host授权→ProtocolAdapter结构校验→Engine CommandDispatcher统一排序→目标领域模块事务。
同一会话内由Engine分配确定性提交顺序；异步任务完成顺序不能直接决定场景写入顺序。

## 4. CommandDispatcher职责
负责接收、请求ID去重、协议/会话前置条件、命令路由、提交顺序与响应关联；不存第二套Scene状态。领域模块执行自己的合法性检查，Engine协调提交与FrameSnapshot发布。
候选接口：submit、cancel、get_status、get_result。对已终结请求返回其已记录的终态，不重新执行副作用。

## 5. 幂等和重试
幂等键建议为(session_id, request_id, principal_scope)。相同键且载荷摘要一致时返回已知状态/结果；相同键载荷不同返回IDEMPOTENCY_CONFLICT。
幂等记录保留时长、跨会话持久化和宿主重启语义仍需在后续工程规范中明确。网络断连不代表执行失败；客户端应按request_id查询状态，不盲目重新创建命令。

## 6. Scene事务
单命令原子。批量SceneTransaction首期默认全有或全无，预先校验ObjectId、ParentId、FrameId、资源租约及expected_scene_revision。
事务失败不产生部分Scene提交；如存在不可回滚的外部I/O，应放在事务外的准备阶段，并以受控资源句柄关联。未来best-effort必须使用明确的不同命令类型，不借助含糊的atomic=false静默启用。
删除含子对象的父对象默认拒绝；级联删除必须显式命令。Frame失效不隐式删除对象。

## 7. Query语义
Query不修改权威Scene、Clock、FrameGraph或ResourceRegistry。查询必须明确session_id和目标快照修订；未指定修订时默认读取最新已发布一致FrameSnapshot。
对大集合采用稳定游标分页，游标绑定snapshot_revision与过滤条件；快照过期返回SNAPSHOT_EXPIRED，不允许跨修订拼接分页。
Query失败不产生写事件；审计访问日志属于宿主而非Scene变更事件。

## 8. ResponseEnvelope
沿用第09阶段字段设计：request_id、status、oneof payload/error。ResponseStatus候选UNSPECIFIED、ACCEPTED、COMPLETED、REJECTED、CANCELLED、FAILED。
响应中可包含command_sequence、committed_scene_revision、frame_sequence和task_id等关联元数据（字段编号待第09阶段统一调整）。
成功响应不得携带最终失败Error；失败响应必须给出结构化错误。异步Accepted后必须允许通过Query或Event获得最终状态。

## 9. EventEnvelope与顺序
事件包含event_id、session_id、sequence、causation_id、correlation_id、occurred_at和类型化payload。每会话提交事件序列单调递增；事件与对应事务的提交结果关联。
事件通知不是命令执行入口，订阅者不能因接收事件直接绕过Engine修改状态。事件至少区分SceneChanged、ClockChanged、FrameInvalidated、TaskStatusChanged、ResourceStateChanged、FramePublished。
事件投递可重复；消费者按event_id/sequence去重。跨网络可靠投递、历史保留与重放范围由宿主策略定义，不承诺无条件exactly-once传输。

## 10. FrameSnapshot发布
Engine在Scene事务和相关Time/Spatial修订一致后发布不可变FrameSnapshot。FrameSnapshot包括session_id、instant、time_generation、scene_revision、frame_graph_revision、resource_epoch、frame_sequence和availability。
FramePublished事件应引用已完成发布的frame_sequence。Rendering只读最新一致快照；旧帧允许视觉回退但必须标记STALE，不能声称为当前科学时刻。

## 11. Error分类与责任边界
| 错误类别 | 示例 | 责任 |
|---|---|---|
| INVALID_ARGUMENT | 缺失FrameId、非有限坐标 | ProtocolAdapter/领域模块 |
| UNSUPPORTED_VERSION | 不支持的Proto契约 | ProtocolAdapter |
| PERMISSION_DENIED | 未授权的资源/命令 | Host，核心复核不变量 |
| UNKNOWN_OBJECT / UNKNOWN_FRAME | 引用不存在 | Scene/Spatial |
| REVISION_CONFLICT | expected_revision不匹配 | Engine/Scene |
| STALE_GENERATION | Seek后旧任务结果 | Simulation |
| INVALID_HANDLE | 已释放对象或资源句柄 | Scene/Resources |
| RESOURCE_EXCEEDED | 超出资源预算 | Resources |
| PROVIDER_UNAVAILABLE | 外部数据源不可用 | Host/数据提供者 |
| CANCELLED | 操作取消 | 对应执行模块 |
| INTERNAL_ERROR | 未预期内部故障 | Engine及对应模块 |
| IDEMPOTENCY_CONFLICT | 相同ID不同载荷 | CommandDispatcher |
| SNAPSHOT_EXPIRED | 游标对应快照不可用 | Query层 |

错误必须保留request_id、稳定错误码、可读说明及必要上下文；不得泄露密钥、内部文件路径或敏感宿主数据。不能以默认枚举0值代表成功。

## 12. 权限边界
Host验证身份、插件能力、网络与资源权限；ProtocolAdapter检查消息版本、结构和类型；Engine检查会话与命令前置条件；Scene/Time/Resources检查领域不变量。消息中的source_capability仅作关联信息，不能替代宿主授权。
AI生成插件未来也只能通过相同SDK与能力边界访问核心，不能新增隐藏写入入口。

## 13. 取消、超时与异步结果
取消命令按request_id或task_id寻址，必须说明目标是否仍可取消。超时是调用方等待超时，不自动意味着任务终止。
TimeGeneration在Seek/Reset/Live切换时递增；异步结果还须检查requested_instant、coverage、provider_version及对象代次。旧数据可留作缓存，但不能错误提交当前Scene。
资源加载Accepted后，Ready/Failed通过ResourceStateChanged事件或Query报告。

## 14. Proto消息设计补充
建议在第09阶段统一补充：
- CommandStatusQuery与CommandStatusResponse，用于异步状态追踪。
- ResponseEnvelope可选command_sequence、committed_scene_revision、frame_sequence、task_id。
- EventEnvelope可选correlation_id与occurred_at。
- ErrorCode补充IDEMPOTENCY_CONFLICT、SNAPSHOT_EXPIRED。
- SceneTransaction首期不允许atomic=false的含糊部分提交语义。
这些属于字段设计建议，不单独创建平行Schema，也不提前冻结字段号。

## 15. 跨模块典型交互
### 创建对象
CreateObject→Host授权→ProtocolAdapter校验→Engine去重/排序→Scene校验唯一ID与父子关系→事务提交→FrameSnapshot发布→SceneChanged/FramePublished事件。
### 时间跳转
Seek→Time更新instant及generation→Simulation旧结果失效→Engine发布新时间上下文的快照（availability按实际数据状态）→ClockChanged/FramePublished事件。
### 异步资源
ResourceRequest→ACCEPTED→Resources加载→READY或FAILED→ResourceStateChanged→必要时更新Scene资源引用。
### 场景查询
SceneQuery→选择一致快照→读取对象→Response，不能修改Scene或发出SceneChanged。

## 18. 第13阶段交互规则对齐
CameraState更新通过SceneCommand.set_camera走Engine统一命令入口，不再定义第二条CameraCommand写路径。RestoreProjectRequest通过Engine受控生命周期流程执行；恢复中不允许直接向Scene注入未校验的持久状态。Engine生命周期事件与FramePublished事件分开，Ready/Running/Stopping不是Command的执行状态；Paused属于Time播放模式。ProjectSnapshot持久化不等于FrameSnapshot渲染快照。
