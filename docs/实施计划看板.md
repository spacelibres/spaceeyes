## 3. 每个增量的固定流程

1. 先写失败测试（Rust 优先；TS 只测 UI/线缆/格式化）。
2. 实现到测试通过；涉及公开契约先改 Proto/MD。
3. 同步 `CHANGELOG.md`、台账状态、进度记录、SDK 技能书；新增能力同步生成类型。
4. `bash tools/check.sh --gpu` 完整通过（含 GPU、SDK 互通、Web 构建、Chromium）。
5. 提交并推送 `development/core-0.0.1`；记录 SHA 与实际验证范围。
6. 在自然检查点用 `gh run list/view` 跟踪同 SHA 的 Rust Core CI；失败则读日志、修复、重跑完整本地检查、追加提交。

## 4. 当前禁止事项

- 在 TS/插件中新增天文、时间尺度、DYN 解码、轨道或数值计算。
- 用显示压缩、合成数据或未验证的近似冒充科学结果。
- 在 M1–M4 未完成前先做市场/AI 闭环。
- 跳过、削弱或沿用修改前的测试证据；不 amend 隐藏失败历史。
