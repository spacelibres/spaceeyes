# 太空之眼平台架构书

状态：总体方向与第一版基线已确认，详细设计按阶段审定。日期：2026-10-28。

## 平台定位

太空之眼（SpaceEyes）是可通过插件扩展的三维仿真平台，覆盖天文学、各类天体与空间任务，不局限于地球、人造卫星或太阳系。通用三维能力与科学算法优先复用成熟外部库。

## 第一版基线

第一版以 NASA Eyes 为唯一显示效果与交互对标，采用太空之眼的 spacelibre VI。学习其天体、航天器、轨迹、光照、标签及选择、聚焦、跟随、缩放、视角切换、时间控制体验，不混用其他产品交互思路。

NASA Eyes 是体验对标，不代表直接复制源码、品牌或未经核对的资源，也不将太阳系数据覆盖当作平台长期范围。

第一版通过独立 TypeScript 数据源插件，运行时按需调取、解码并求值 DYN 数据，经平台 SDK 驱动 Bevy 展示。具体端点、格式版本、分段语义、时间尺度、参考系、单位和使用条件须以实际来源和样本核验，不能根据旧文档直接认定已支持。

实时调取指按对象和时间范围获取数据、缓存并依来源更新情况刷新，不要求逐帧下载，也不把预测或插值结果称为实时遥测。

## 架构与职责

| 部分 | 技术方向 | 职责 |
|---|---|---|
| 网页宿主 | TypeScript + Next.js | 工作区、页面交互、数据源插件管理与 SDK 接入 |
| 客户端三维显示核心 | Rust + Bevy → WASM | 场景、模型、相机、材质、光照、选择交互与结果显示 |
| 数据源插件 | TypeScript | NASA DYN 等数据的获取、解析、求值和标准化；不直接操作 Bevy 内部状态 |
| 服务器计算模块 | Rust + Nyx | 后续阶段提供独立的科学计算任务与结果；不编译进客户端、不与 Bevy 链接打包 |
| 平台 SDK | 面向 TypeScript | 受控显示与数据能力；后续增加计算任务能力 |

Bevy 内部 Rust Plugin 与平台 TypeScript 插件是两种不同机制。具体领域功能通过 SDK 扩展，不预先把所有科学功能塞进显示核心，也不把插件局限为界面。

## 两条数据路径

第一版：选择对象与时间 → DYN 数据源插件按需获取、解码和求值 → 标准化状态 → 平台 SDK → Bevy 展示。

后续：客户端通过 SDK 提交任务 → 服务器调度 Nyx → 返回任务状态及结果 → SDK → Bevy 展示。Nyx 计算不依赖浏览器帧率、相机或播放速度。DYN 数据不必经过 Nyx 重新计算。

显示接口显式保留时间、单位、参考系、数据来源与有效范围。科学状态和显示坐标分离，转换时明确原点、比例与轴向；缺失或超出覆盖的数据不得伪装为有效状态。

## SDK、技能书与大模型

插件通过公开 SDK 使用平台能力，不获得 Bevy 或服务器内部对象。SDK 技能书明确能力、参数、权限、资源归属、错误、示例与验证要求。技能书解释规则，运行时落实规则。

Bevy 技能用于显示核心开发，Nyx 技能用于服务器科学计算，平台 SDK 技能用于人工和大模型编写插件。生成插件与人工插件执行相同的权限与验证流程。

Proto 是公开结构化契约的候选方案，尚未最终确定；不将全部 Bevy 内部操作包装成消息。大数据传输机制另行设计。

## 阶段边界

当前先整理规划与验收，再完成 NASA Eyes 基线下的三维浏览、DYN 按需加载和播放。服务器 Nyx 计算、STK 等计算工具、完整插件市场与大模型自动化为后续阶段，不进入第一版验收范围。

第一版保留独立数据源插件与 SDK 边界，但不以完整插件市场作为前提。具体依赖版本、页面布局、性能指标和接口字段在对应阶段设计，不提前宣称完成。
