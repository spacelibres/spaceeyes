# NASA Eyes 全量卫星与航天器接入设计

状态：用户已确认并完成本批实现；实际验收与三项源缺失见 evidence/eyes-expansion-0.0.19/README.md，不代表全对象 GPU 或科学精度认证。日期：2026-10-30。

依据《太空之眼平台架构书》《第一版规划与验收》及用户接入全部 NASA Eyes 天然卫星、人造卫星、飞船和模型的要求。保持 Bevy 显示核心、独立 TS 数据插件、受控 SDK、服务器资源和按需加载，不涉及 Nyx、市场与大模型实现。

## 范围与已核验清单

范围为当前 NASA Eyes Solar System 参考目录中的 Moon 与 Spacecraft。人造卫星是 Spacecraft 的任务类别，不能仅按名称另猜目录。其他 NASA Eyes 应用的独立目录、参考仓库自加的 Starlink 星座不自动冒充 NASA Solar System 原始对象。

对本地参考源码只做静态语法树读取，不执行其注册函数。EntityCatalog 共 724 项；本批目标 622 项：451 天然卫星、171 航天器。619 项找到实体定义，601 项声明模型入口，去重 131 个 glTF URL；18 项采用球面表面贴图。426 个小卫星使用三个通用不规则模型之一，这是源定义，不可标为实测形状。3 项只有目录、未找到实体定义：sc_isas、sc_lunar_trailblazer、sc_lunir；须继续寻找已声明来源，不能猜造路径并报告成功。

上述数字是固定参考快照的静态清单，不是已下载模型数或远端成功数。原始抽取数据保存在本次分析的 `validation/results/eyes-target-inventory.json`，实施时须形成可复核的版本化来源清单与生成工具，构建不依赖开发者的另一个本地仓库。

## 推荐方案

采用全量目录、按场景加载。一次登记全部目标及必要父体依赖；搜索、分类、行星系统与关联对象可访问全部目标。初始仍显示太阳系；进入行星系统加载其卫星，选择航天器加载对应任务轨道、姿态与模型，返回/切换释放不再需要的表示。

相比启动即请求 622 个对象和所有模型，此方案遵循既有资源边界，避免首屏阻塞和轨迹预算超限。只加几个手工样例无法满足全量目录要求；样例仅用于逐批验收，不缩减最终清单。

## 数据与科学状态

- 将目录与资源描述从固定十对象列表中分离为独立领域数据，保留对象类别、来源、真实半径/范围、父体时间表、轨道/姿态控制器、可用模型和贴图。
- 95 个目标含多段父体时间表。当前父体由统一仿真时刻选择，递归求值并检测循环；飞越、入轨和着陆不得仅用 URL 第二段或固定 parentId 推断。
- DYN 按实体声明的路径和覆盖选择控制器；支持实际所需的位置/速度类型及分段，不能全部拼接为 `{id}/{parent}/orb`。例如 ISS 声明路径 sc_iss，不是目前假设的 sc_iss/earth/orb。
- 固定位置、轨道要素、姿态对准、自转与控制器优先顺序按恢复源码和真实样本核验后实现；不把未知表达式转成零状态。任务时间外显示真实覆盖，并支持跳到有效任务时间。
- 卫星相对父体、航天器任务轨迹与太阳系统一 km 科学状态；总览 AU 只用于显示。瞬时闭合椭圆仅适用于合适的有界运动，飞越/转移/着陆不强制画闭合环。
- 现有金星/火星固定源哈希区段选择继续保持；新对象异常逐项分析，不放宽通用解码规则。

## 模型和资源

- 按源定义的实际 131 个入口展开 glTF buffers、images、扩展、节点、场景与动画；记录原始 URL、SHA256、字节、模型单位、缩放和轴向修正。
- 注册清单不触发下载。服务器按已审查资源路径读取并缓存，浏览器通过受控同源资源入口按需请求；共享模型及贴图复用，不打包进 WASM，不一次加载整个目录。
- 球面卫星使用各自声明的六面贴图；火卫一/二等非球形天体使用模型。通用模型明确为源提供的示意几何，不能冒充观测重建。
- Bevy 按锁定版本支持 glTF，并核验实际 Draco、纹理压缩及材质扩展。优先采用成熟库或服务器离线转换，保留转换来源及散列，不自研通用三维解码器；未支持资源明确失败。
- 模型局部旋转、非均匀缩放与平移须同对象科学姿态分开，经受控描述传入 Rust 显示，不给插件访问 Bevy World 或任意 shader 的权限。

## 交互、生命周期与预算

保留现有品牌、全窗口工作区、聚焦/跟随、画布点选、时间播放和返回总览。扩展分类、搜索、父体系统与任务时间入口，目录/场景选择同步。可用性分别报告目录、数据、模型、GPU，不用球体冒充已成功加载飞船。

轨迹最多 4096 点/会话及模型资源预算不直接删除；按可见系统和选中对象分配预算。请求使用有界并发、取消信号和修订令牌；快速切换、退出、跳时不能复活旧模型或覆盖当前任务状态。

## 交付与验收

按同一全量清单迭代，不把少量样例完成称为全量完成：

1. 全量目录及资源审计：622 目标逐项有来源和明确状态；缺项不计成功，父体依赖完整，131 模型入口逐项核验。
2. 天然卫星系统：木星四大卫星、土星卫星及火卫一/二作为回归样本，再覆盖剩余目标；球面/非球形显示、父体、轨迹、选中、时间和返回完整贯通。
3. 航天器：ISS、Juno、Voyager、跨父体飞越与着陆任务作为回归样本，再覆盖剩余目录；验证模型依赖、姿态/局部变换、实际覆盖、历史任务跳时。
4. 全量集中验收：清单报告每项目录/数据/资源/GPU结果，核对失败与缺失；跑完整 Rust/TS/WASM、资源、Next 和实际 GPU，检查启动不下载所有模型、共享资产复用、取消/退出及预算。

每个验证通过的实现版本递增补丁、更新 CHANGELOG、提交推送当前分支并通过 gh 跟踪 CI。缺少源数据或不受支持资源的条目保留可追溯状态，不伪造“全部通过”。
