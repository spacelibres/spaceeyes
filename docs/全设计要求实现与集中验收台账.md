依据平台架构书、技术可行性G0—G5、已批准ADR-001—009、模块专项规范及开发进度M1—M7核对。静态代码存在不等于用户路径验收通过；基础原型通过不等于完整规范完成。历史实现段落仅作为当时记录，本表及开发进度首页记录当前范围。已验证基线d4a8ac965dd0ea4c353a906bffafbd84f665eadc，开发分支CI：https://github.com/spacelibres/spaceeyes/actions/runs/40511115744 。新增候选按自己的SHA另验，不能沿用基线结果。

状态：已验收=所列有限范围有实际测试；部分=有机制或原型但未达到完整出口；未实现=只有设计；核验中=外部证据不齐。下面覆盖所有现有设计文档族；新功能必须关联条目、代码与集中测试。

## 分批实施顺序

2026-10-28 项目负责人接手指令：核心计算、天文、时间、解码全部用 Rust；TS/Next.js 只做交互与界面；插件市场只做交互、皮肤与显示。由此重排如下（与旧顺序冲突处以本表为准）：

1. **M0 职责边界与基线（本轮）**：`docs/核心与宿主职责边界规范.md`、架构书§17、本台账、进度与CHANGELOG同步；确认基线全量检查通过。出口是文档一致且无代码行为变化。
2. **M1 Rust 科学时间**：UTC/TAI/TT/TDB、闰秒、J2000、历法、Proto只读换算查询；全部Rust测试（已知历元、闰秒、边界、往返）。出口是TS不再做任何时间换算。
3. **M2 Rust DYN 核心**：`crates/dynamo` 解析/求值/分段/覆盖/错误；与现有TS包在同一合成与本地真实样本上逐项对照。出口是Rust结果覆盖五类点与异常边界，TS仅作oracle。
4. **M3 DYN 接入核心**：宿主代理取字节→有界上传→Rust解码求值→提供者样本；浏览器移除JS科学计算；取消/迟到/来源/覆盖负向测试。出口是浏览器用户路径不再依赖TS天文代码。
5. **M4 太阳系首期**：Rust目录与轨道采样、核心线图元、科学时间轴（UTC日期输入/显示）、来源与覆盖面板、聚焦/跟随。出口是选定天体与时段的完整用户路径与可解释误差证据。
6. **M5 稳定与规模**：设备丢失重建、LOD/多尺度深度、缓存与预算、目标设备/场景规模性能实测。
7. **M6 UI插件与市场**：iframe/Worker沙箱、贡献点渲染、制品签名/锁、精确安装/升级/回滚；插件只做UI/交互/皮肤。
8. **M7 AI技能闭环**：版本化技能书、隔离构建、限次修复、受控安装与审计；生成范围限UI/交互插件。

旧顺序中的“先市场/AI、后科学”不再采用；插件市场不得先于M1—M4的核心科学路径。

## 集中测试与提交纪律

每个增量：先失败用例→局部测试→相邻模块和真实用户路径→独立规格/代码审查→tools/check.sh --gpu全部通过→直接提交推送开发分支→立即继续下一项开发，同时在自然检查点用gh核验尚未结束提交的Actions结果。失败及时读日志修复、重跑本地检查后追加提交。verify_remote_ci仍严格核验push事件及完整SHA，但不阻塞提交或本地开发。保留失败历史，不amend复用旧证据，不长期维护验证分支。任何新增要求或能力都更新本表、实施计划、CHANGELOG与SDK技能书。用户最新流程覆盖早期双门槛记录。

外部证据需要：参考TS固定提交与逐文件许可、真实五类样本摘要、权威时间/参考系和NASA/JPL对照、明确误差容限、真实目标设备/规模，以及后期模型/市场服务配置。当前不因缺这些输入停止M3自主实现，也不据此宣布整个设计已经完成。
