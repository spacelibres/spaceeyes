# 第一版后续贯通实施计划

日期：2026-10-29。依据：太空之眼平台架构书、第一版规划与验收；本计划不替代架构书，不将局部验证视为第一版全部完成。

## 实施与集中检查

1. 模型取景：从 Bevy 已加载网格包围范围和层级变换计算显示范围，科学半径不变；验证偏心模型、单位比例、目标/资源切换、缩放及无数据状态。修改核心相机与相应测试。
2. Next.js 工作区：新建独立 web 目录，复用 platform 的宿主/SDK 与真实 WASM；提供目录选择、聚焦、时间控制、资源反馈及离开清理。应用批准的 spacelibre VI。只有合成采样时明确标记技术验证，不提供假的真实天体轨迹。
3. 数据插件：以资源地图和真实样本为准，明确受支持类型、时间/参考系/单位、分段及覆盖；先测试真实样本与错误，再实现受控获取、缓存、取消、求值和 SDK 发布。缺少科学语义时明确阻塞项，不推测补齐。
4. 场景贯通：按已核验数据实现目录、运动/姿态、资源、时间、相机与面板协作；地月流程是规划中的候选，数据不齐时先补证据，不虚构覆盖。轨迹和图层随后沿完整流程扩展。
5. 集中验收：每批执行 Rust/TS/WASM/资源检查及适用 GPU 流程，工作区补构建、类型、交互与生命周期检查；记录实际环境与截图。新增行为通过后递增补丁版本，写 CHANGELOG，提交推送当前规划分支；gh 在自然检查点复核 CI，失败追加修复。

## 共用约束

Rust 是场景权威，TS 插件只使用受控 SDK；新增公开能力同步技能书。复用 Bevy，不另写三维引擎。资源来源、失败和过期状态可见；ready 不代表完整视觉或科学语义通过。保留原始第三方许可，不提交缓存原始资产。

不触碰冻结的 development/core-0.0.1，不使用旧 apps/packages 残留作为新工作区。Nyx、STK、市场、大模型自动化仍是后续范围。性能、科学误差与 NASA 成对截图验收不能以本计划或技术演示替代。
