# 平台基础功能实施

依据：太空之眼平台架构书、第一版规划与验收。当前工作分支为 `codex/bevy-planning`，本实施不依赖冻结开发分支。

平台基础建设服务全部天体和任务插件，不把资源格式实验或个别天体页面当作平台主体。以下是原规划的实施分解，不变更架构和第一版范围。

| 基础能力 | 责任与依赖 | 验收依据 | 当前状态 |
| --- | --- | --- | --- |
| 插件宿主 | TS 注册、兼容检查、授权、启停及清理；不持有场景权威状态 | 启停、失败回滚、授权及旧会话失效测试 | 已有进程内启停、整体关闭及在途任务清理；尚未接入正式页面 |
| 受控 SDK | 宿主校验调用及资源归属，Rust 核心再次验证结构化输入；同步技能书 | 非法调用被拒绝、跨插件资源不可修改、错误可追踪 | 已接通真实 Rust WASM，含数据发布/删除、时间和聚焦意图；显示资产句柄待实现 |
| 三维核心 | Rust/Bevy→WASM；通用场景、资产、相机、光照、选择和卸载 | 浏览器实际加载、GPU 画面和资源释放证据 | 已接入 Bevy 0.19.1 与浏览器，基础球体、材质、光照、聚焦和清理有实测证据；真实资产等仍待实现 |
| 对象与科学状态契约 | 通用对象标识、时间尺度、参考系、单位、来源及覆盖；科学状态与显示坐标分离 | 数据可追溯、覆盖外明确失败、Rust 验证转换输入 | 已有 ICRF/千米/TDB 采样状态、归属及局部原点显示转换；姿态和轨迹待实现 |
| 时间与相机协作 | TS 提交操作意图，核心执行；数据插件按统一时间求值 | 暂停、播放、跳时、聚焦、跟随及尺度稳定性 | 统一时钟与 SDK 控制已验证；基础聚焦、环绕和缩放已实测，完整 NASA Eyes 相机交互尚未验收 |
| 资源服务与数据插件 | 受控获取、缓存、取消、解码、求值和生命周期归属 | 真数据、失败反馈、过期结果拒绝及停用清理 | 只有离线样本验证，不视为平台接入 |
| Next.js 工作区 | 承载三维画布、对象目录、信息、图层、时间控件及插件状态 | 页面与核心状态一致、路由离开与重新进入正确释放 | 待实现 |
| 构建与集中测试 | 锁定依赖、Rust/TS检查、WASM构建、浏览器/GPU验证及 CI | 按最新用户要求执行适用检查、更新 CHANGELOG 并提交，提交后 gh 复验 | 已建立 check-core.ps1 和 Core Foundation CI；浏览器/GPU 仍未覆盖，不将其缺失当作通过 |

实施依赖：先建立插件生命周期和测试，再定义 SDK/核心协作契约及技能书；按契约打通 Rust/Bevy WASM 与 Next.js；随后接入资源服务和数据源插件，补齐时间、相机及面板。契约设计时同时核对所有基础能力，不能各自另起不兼容协议。Proto 的取舍按架构书单独确定，当前 TS 类型不作为已批准的最终公开协议。

首批文件为 `platform/plugin-host.ts` 和 `platform/tests/plugin-host.test.ts`。宿主注册时复制清单；启用时检查声明能力是否获宿主批准；每次启用创建独立 AbortSignal；停用或启动失败先撤销会话，再逆序尝试全部清理；同一插件并发启停明确失败，不悄悄交错。资源通过清理回调归属会话，实际 SDK 对象句柄隔离仍待实现。

宿主不加载远程代码、不执行市场安装、不提供沙箱。`camera.control` 对应受控聚焦意图，`data.publish` 对应采样状态发布和删除，`time.control` 对应时间操作。核心适配接口为内部边界，未选择最终公开传输协议；真实 Rust 实现会再次验证对象及调用会话。不得把检查方法当作能约束同进程任意 JS 的安全边界；未来市场和大模型插件须在隔离执行与 SDK 通道建立后接入。

本批局部验收命令：`node --test platform/tests/*.test.ts`。它验证生命周期逻辑，不替代 Rust、WASM、页面或 GPU 验收，不代表基础平台全部完成。
