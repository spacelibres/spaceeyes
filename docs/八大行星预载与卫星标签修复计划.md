# 八大行星预载与卫星标签修复

用户本轮明确要求初始化加载八大行星资源、恢复人造卫星名称；沿用已授权NASA对齐范围，不新增SDK或外部计算。

## 原因与方案

solar-workspace详细对象集合为空，只有选择才加载姿态/六面表面/土星环。改为八大行星初始驻留，DYN轨道与姿态、高清表面及土星环在总览启动即请求；太阳保持程序化表面、月球与航天器模型继续按需。资源留服务器，不嵌入WASM。已有有界服务器队列、逐帧转换、缓存和生命周期保持，启动不并发无限请求。显示八颗资源准备/失败数，不能把启动耗时当作全部贴图就绪；跳转不重新升级或创建已驻留表面。卫星数据仍按场景渐进加载，不阻塞主行星选择。

renderer在sc_对象投影半径不足0.8/1.2像素时直接跳过，连同远距标记、拾取与名称全部消失。以固定小标记代表未解析对象，不以模型像素半径判定标记可见性；有效数据、ready表示、视野、遮挡和局部系统范围仍需满足；标签继续选中/近景隐藏、固定锚点碰撞与渐隐。失败表示不伪造可见。

## 执行与验收

1. 先改宿主集成测试，要求启动有且仅有八颗详细资源、八颗姿态已请求，切换与返回不重复表面，月球/航天器仍按需。
2. 核心测试要求亚像素对象保留表示资格，失败/不可投影/遮挡仍不显示；不改已有标签碰撞布局算法。
3. 实现初始驻留和资源进度、移除错误光栅门槛；更新SDK说明中的宿主预载策略，不改变插件权限。
4. 完整本地检查、独立审查、真实WASM总览预载到8/8、连续八颗跳转、地球卫星标记/名字/遮挡/选中、ISS/MRO、退出重入。记录错误与资源驻留成本，不把卫星异步加载冒称瞬时完成。
5. core/web补丁版本递增、CHANGELOG、提交推送当前分支，通过gh跟踪CI。
