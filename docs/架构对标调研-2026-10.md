# SPACEEYES 架构全球对标调研（2026-10）

版本：0.0.1｜状态：调研记录（非受控实现文档）｜日期：2026-10-28
说明：本文件未提交 Git，不改变任何 ADR 或版本。
目的：回答两个问题——(1) 全球是否存在与 SPACEEYES 同构架的工程；(2) 当前设计处于什么水平。
方法：以本仓库 `docs/` 规划书中的 8 个架构特征为坐标，检索并核对 2026-10 时点可公开访问的项目官网、文档与仓库元数据；对无法核实的点明确标注“未证实”，不以搜索摘要代替证据。

## 0. 结论先行

1. **没有找到一个与 SPACEEYES 完全同构架的单一工程。** 即“单一 Rust 核心（Native/WASM 同源）+ Protobuf 唯一公开契约 + Next.js/React 宿主 + 沙箱化 TS 插件市场 + 版本化技能书驱动的 AI 生成 + 太空科学场景”这个组合，在公开项目中未被任何一方完整占据。
2. **你的设计属于“组合先进、单点不领先”。** 每个支柱都能找到成熟甚至领先的对照物：Rust/WASM 有 Bevy/wasvy，浏览器太空有 NASA Eyes/OpenSpace/Stellarium Web，Web 插件沙箱有 Figma，AI 扩展生态有 MCP/Agent Skills/Claude Marketplace/Omniverse Skills。你的价值在交叉点，而不是任何单点技术首创。
3. **“先进性”目前主要成立在设计与工程纪律层面，尚未成立在科学数据、性能和生态层面。** 科学时间/星历/参考系、真实数据管线、渲染规模、插件沙箱、市场与 AI 闭环，均处于“设计完成、实现未完成”。
4. **竞争窗口正在收窄。** MCP 已成为 AI 工具/应用的通用协议，Agent Skills 已成为跨平台技能标准，Claude Marketplace 已有 500+ 一键安装插件，NVIDIA 也在用“Agent Skills”封装 Omniverse 能力。两年后，“AI 能生成插件”将不再是卖点；能留下来的差异是**领域正确性 + 可组合性 + 零安装**。

## 3. 逐维度判定

| 维度 | 判定 | 依据与说明 |
|---|---|---|
| A 单一 Rust 核心跨 Native/WASM | **先进（稀缺）** | Bevy/Rerun 证明 Rust+WASM 可行，但“同一权威核心同时服务 Native 与浏览器，且协议一致”在太空仿真领域未见同构者；LunCoSim 是 Rust 但路线偏桌面协同仿真。 |
| B 浏览器实时三维 | **持平偏后** | wgpu/WebGPU 是正确方向；但 Cesium/PlayCanvas/three.js 的规模、工具与兼容性积累远超当前实现；你尚无公开性能基准。 |
| C Proto 唯一契约 | **工程上先进，技术上常规** | 单一 Schema + 生成两端类型是 gRPC/Connect/buf 生态的成熟做法；在“仿真核心 + 插件市场”里坚持单一契约，比多数开源项目严谨。 |
| D TS/React 宿主 + SDK | **持平** | OpenSpace 已有 JS/TS API 与自定义 Web UI；你的差异是 SDK 不持有第二套状态、能力协商与错误结构化。 |
| E 插件市场 | **落后（未实现）** | Figma/Claude/Omniverse 已有可运行市场；你的制品签名、锁文件、迁移、回滚仍是设计。 |
| F 插件隔离 | **落后（同进程）** | Figma 用受限 JS 沙箱 + iframe；wasvy 用 WASI 组件；Extism 用 WASM。你的 `packages/plugin-host` 是可信同进程宿主，自己也已声明“不是沙箱”。 |
| G 技能书 + AI 生成 | **方向先进，实现为零** | Agent Skills 已把 `SKILL.md` 变成开放标准，Omniverse 也发布官方 Agent Skills；你的“版本化技能书 + 权限负向测试 + 受控安装 + 回滚审计”在设计上比多数生态更严格，但尚未跑通。 |
| H 太空科学 | **明显落后** | OpenSpace 有 SPICE/星历/球面/任务；NASA Eyes 有官方数据；你目前只有 DYN 解析/求值与合成样本，TT/TDB/UTC、J2000、误差容限、真实样本许可均未闭环。 |
| 工程纪律（测试/ADR/来源台账） | **先进（同类少见）** | 每次提交完整本地检查、ADR 批准记录、第三方来源台账、失败历史保留；这在同类开源太空项目中并不常见，是真实优势。 |

## 4. “是否先进”的分项回答

- **架构新颖度：高。** 没有同构架者；把“Rust 单核心 + Proto 契约 + 插件市场 + 技能书 AI 生成”压到“浏览器太空探索”这个场景，是空白区。
- **单点技术领先度：中。** 大多数选择是“正确且主流”，不是首创；真正有原创性的是治理组合（能力协商、幂等/代次、来源策略、技能书验收），而不是渲染或 ECS。
- **科学领域领先度：低—中。** 与 NASA Eyes/OpenSpace 不在一个量级；这是最容易被质疑“先进性”的地方。
- **生态与市场领先度：低。** 市场、隔离、AI 闭环均未实现；而外部生态已经把“AI 扩展”标准化。
- **综合判断：** 你的设计**方向先进、组合稀缺、工程严谨**，但**产品先进性尚未被科学数据、性能证据和生态规模证明**。当前更准确的表述是“有潜力的差异化架构”，而不是“全球领先的平台”。

## 5. 竞争威胁（按紧迫度）

1. **AI 扩展商品化。** MCP + Agent Skills + Claude/OpenAI 市场 + Omniverse Skills 已把“模型生成并安装扩展”变成平台标配；如果 SPACEEYES 的卖点只是“AI 写插件”，会被通用生态吸走。
2. **官方免费体验。** NASA Eyes 免费、官方、数据权威；你的太阳系首期必须在其强项之外提供“可扩展/可编程/可离线/可嵌入”的价值。
3. **科学正确性门槛。** 一旦对外宣称“真实太阳系”，TT/TDB/UTC、光行时、参考系、误差容限会被专业用户逐项检验；合成数据或显示压缩必须显式标注。
4. **插件安全。** 同进程 TS 宿主无法约束恶意插件；在开放市场前必须完成 Worker/WASM/iframe 隔离与权限负向测试，否则一次安全事故会摧毁市场信任。
5. **范围过大。** 引擎、科学、市场、AI 四条线同时推进，容易出现“每条都 60%”的状态；OpenSpace 用十余年才做到今天的科学与内容深度。

## 6. 保持“先进”的建议路线

1. **先打穿一个垂直切片，而不是铺平台。** 以“太阳、行星、月球 + 真实 DYN + 科学时间轴 + 来源/有效范围面板 + 聚焦跟随”为 M4 出口，直接对标 NASA Eyes 的首屏体验；市场与 AI 后置。
2. **科学可信度做成卖点。** 用 JPL Horizons/SPICE 建立误差基准与回归样本；界面显式标注“显示压缩/非科学尺度/数据来源与时段”。这比再多的 PBR 材质更能建立差异化。
3. **插件沙箱提前。** 优先走 WASI Component Model（wasvy/Extism 路线）或“Worker + WASM + iframe UI”，权限清单参考 Figma 的 manifest 网络白名单；同进程宿主只保留给官方受信插件。
4. **对齐外部标准，降低生态成本。** 技能书直接兼容 Agent Skills 的 `SKILL.md` 结构；工具面用 MCP 暴露；科学数据用 SPICE/DYN 而不是自造格式。这样 AI 生成与第三方工具接入都不需要重新教育生态。
5. **公开性能基准。** 给出目标设备、对象数、帧时间、内存/显存峰值、首屏与加载时间；没有这些，“先进架构”无法被外部验证。
6. **市场先私有后公开。** 先做项目内私有插件 + 锁文件 + 摘要校验 + 回滚，再谈公开市场与审核；避免在协议未稳定时背上治理成本。

## 7. 一句话结论

**全球没有与你完全同构架的工程；你的组合是稀缺且方向正确的，但“先进”目前体现在设计与工程纪律，而不是科学数据、性能或生态。** 真正的护城河应押在“可验证的科学 + 可组合的插件 + 浏览器零安装”，而不是“AI 生成插件”本身——后者正在被 MCP 与 Agent Skills 商品化。
