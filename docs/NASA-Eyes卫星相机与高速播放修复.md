# 卫星相机与高速播放修复 0.0.46

用户复现：Chandra附近视角FOV100，地球在屏幕边缘拉伸；MRO TDB847045665.6641246、倍率57600、nearby视角混乱。架构及天然主星关系不改变；不重新缩放或压扁主星、不以编造坐标掩盖。

## 根因与修正

1. 碰撞检测用上一帧绝对相机位置连到当前帧位置，却使用当前时刻天体球。高速轨道的时间推进弦穿过主星，误判用户穿透。保存前次焦点/原点/安全位置，同一焦点把起点按原点位移搬到当前目标参考系；真正鼠标移动仍扫掠，目标切换仍沿物理空间过渡。CameraBlend的过渡起点同步随目标运动，避免以过时世界位置追赶高速目标。
2. 摄像机far仅依赖米级航天器取景范围，未保证数千公里主星落在可见范围；按当前真实天体球范围补足far。逆无限投影保留，near继续按碰撞间隙保护。
3. 恢复NASA CameraComponent.js:338-360按画面长边定义FOV；旧实现把同数值当作Bevy竖直FOV，宽屏100度被扩成134度等超宽横向视野。按aspect换算竖直FOV，默认/手动数值及API不变。银河/恒星读取同一个有效投影。直线透视在大视场边缘仍有正常离轴拉伸，不宣称所有位置球体都投影为圆。
4. 主星Follow视角侧向构图偏移按有效横向视场约束，避免窄视场或竖屏把航天器推离屏幕；保留父体方向和手动环绕。
5. 高速自动跨覆盖段加载时可立即暂停；重载完成使用最新播放意图，不能把捕获的旧播放状态恢复回来。加载时LIVE禁用、暂停按钮保留可用，其他依赖数据操作仍受控。

## 验证

先复现小目标far不含主星、100度变成超大横FOV、加载时暂停被拒绝的失败。新增同焦点大相位轨道推进12帧不发生虚假碰撞、真实穿过目标仍被拦、过渡平移不滞后、横竖屏NASA投影系数及暂停请求回归。集中Rust/TS/WASM/Next/真实资源检查和实际Chandra/MRO浏览器验证；结论与限制见evidence/orbital-camera-0.0.46。
