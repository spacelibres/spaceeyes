## 目标与边界
先消除跨Engine同任务ID结果误收、任务ID重用后的旧回调、同ID对象删除重建后迟到写入三类缺口，作为真实异步执行器前置。本增量不宣称实现网络/Worker、严格科学来源、确定并行提交队列或完整任务Proto。

Rust SimulationScheduler为每次入队签发不透明TaskExecutionToken，绑定调度器实例身份与单调序号；forget/clear不重置序号。TaskRequest保留任务ID/时间/依赖输入，发给TaskExecutor的是包含请求与token的IssuedTask。TaskResult及Failed/Cancelled反馈必须带token；校验不匹配不得改变目标任务状态、依赖、Scene或资源。相同任务ID与时刻/TimeGeneration不足以证明执行身份。Rust宿主仍可显式按当前任务ID取消，异步回调必须使用token。request_cancel通知携带IssuedTask，取消先提交状态再通知。

Engine普通enqueue_task采用保守边界：记录入队SceneRevision及FrameGraphRevision，提交前不允许上下文已经变化；这对创建对象的旧任务保持安全，不能借调用者提供的最新修订绕过绑定。另提供enqueue_task_for_objects(request, targets)给既存对象任务，捕获明确ObjectHandle及当时完整SceneObject值并去重/限额。校验全部句柄、目标/声明依赖对象的原始值及图修订，允许无关对象变更，但提交的写目标/父级/跟随依赖必须属于声明集合；该模式禁止Create，创建任务使用普通修订绑定路径。身份与句柄须在结果接受及最终提交重复校验，commit_task_scene必须携带执行token。目标声明原始长度最多1024，去重或重复拒绝不得绕过长度约束。

目标失效标记Stale并传播依赖失败、清理租约；错误执行token不使本实例合法任务Stale。纯输入/Scene事务错误保持原子、ResultReady可显式重试。终态遗忘、取消、失败、Seek和Stop回收关联上下文，restore创建新实例与新执行身份，不能接收旧会话任务。严格科学来源provider版本/coverage策略和确定并行提交顺序保留C06后续工作，不以可选provenance冒充完成。
