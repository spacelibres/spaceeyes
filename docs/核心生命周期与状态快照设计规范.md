# SPACEEYES 核心生命周期与状态快照设计规范

版本：0.0.1｜状态：第12阶段设计草案｜日期：2026-10-27
范围：仅Markdown设计，不创建Rust、Proto或测试文件。
依据：第08阶段对象模型、第09阶段Proto设计、第10阶段命令事件规范、第11阶段工程目录、已批准ADR-001至ADR-009。

## 1. 目标与边界
统一Engine会话生命周期、Scene对象生命周期、Simulation任务与Resources释放顺序，定义只读FrameSnapshot和持久化ProjectSnapshot的职责、内容、恢复语义。不得将GPU临时状态、NASA DYN文件或插件运行时内部对象混入Rust核心权威状态。

## 2. Engine生命周期
状态：Created、Initializing、Ready、Running、Stopping、Stopped、Failed。
Created→Initializing→Ready→Running→Stopping→Stopped为正常流程。Initializing或Running可进入Failed；Failed经受控清理进入Stopped，是否允许重新初始化需后续明确。
Paused属于SimulationClock的播放模式，不是Engine生命周期状态；停止渲染与暂停仿真也不是同一操作。
状态迁移由Engine统一协调，宿主只通过公开命令请求，不能直接修改生命周期字段。

## 3. 初始化顺序
建议：
1. 验证Engine配置、会话身份和协议能力。
2. 建立foundation值类型上下文与Time权威时钟。
3. 建立Spatial参考系图、Scene注册表和Resources管理器。
4. 建立SimulationScheduler及任务预算。
5. 初始化Rendering设备适配和可恢复资源描述。
6. 建立ProtocolAdapter公开入口并发布初始一致FrameSnapshot。
7. 进入Ready，收到运行命令后进入Running。
具体模块构造依赖由Engine组合，不允许反向循环依赖。初始化失败必须释放已创建资源，不得暴露半初始化Engine为Ready。

## 4. Engine状态与命令约束
| Engine状态 | 允许操作 | 禁止操作 |
|---|---|---|
| Created | initialize | 场景写入、渲染 |
| Initializing | 状态查询、取消初始化 | 常规业务写命令 |
| Ready | 查询、合法命令、start、shutdown | 未授权直接写入 |
| Running | 命令、查询、advance、render、shutdown | 绕过Engine写入 |
| Stopping | 状态查询、等待清理 | 新写命令、新任务 |
| Stopped | 只读终态信息 | 写命令、资源使用 |
| Failed | 故障查询、受控清理 | 正常运行命令 |

## 5. SceneObject生命周期
Created→Attached→Active→Detached→Disposed为候选逻辑状态。对象身份由稳定ObjectId表示，内部ObjectHandle带代次；Detached可重新Attached时是否保持同一ObjectId需统一规则。
删除父对象默认拒绝存在子对象的情况；显式级联删除需以Scene事务提交。FrameId失效仅使对象空间状态unresolved，不自动删除对象。Disposed对象的内部句柄立即失效。

## 6. Simulation任务生命周期
任务从Created、Validated、Queued、Running、ResultReady、Committing进入Completed；Cancelled、Failed、Stale为异常终态。任务不得持有Scene可变引用。Seek/Reset/Live源切换增加TimeGeneration；旧代次结果不能提交。连续播放同代次结果还需检查目标时刻与数据覆盖。
Stopping时禁止新任务，取消可取消任务，拒收迟到结果，释放资源租约。

## 7. Resources生命周期
资源由ResourceManager唯一管理：Declared→Loading→Ready→Evictable→Released；异常状态Failed、Cancelled、Invalidated、Recovering。
Scene删除对象释放租约，不直接销毁其他对象共享的资源。GPU设备丢失使GPU句柄失效，资源描述与可恢复CPU数据可保留。资源恢复不得修改Scene科学状态。

## 8. 三类快照
### SceneSnapshot
Scene生成的只读对象集合、组织关系、空间状态引用、资源逻辑引用及scene_revision。它不单独代表完整科学帧。
### FrameSnapshot
Engine在一致提交边界原子发布，包含session_id、simulation_instant、time_generation、scene_revision、frame_graph_revision、resource_epoch、frame_sequence、availability，以及只读Scene/Spatial状态引用。Rendering只消费完整一致快照；旧帧显示须标记STALE。
### ProjectSnapshot
用于持久化项目和重新打开。保存场景对象稳定ID、组织关系、FrameId、时钟状态、相机逻辑状态、资源描述与来源引用、项目元数据和Schema版本。不得保存Rust内部代次句柄、GPU指针、网络连接、运行线程、插件执行栈或不可恢复的临时缓存。

## 9. FrameSnapshot发布顺序
Host授权→ProtocolAdapter校验→Engine统一命令排序→Time/Simulation处理→Scene事务提交→Spatial修订一致性确认→Resources引用状态确认→Engine原子发布FrameSnapshot→FramePublished事件→Rendering读取。
若状态不一致，不得发布伪造的COMPLETE帧。可以保留最近一致旧帧作为视觉回退，但必须明确STALE。

## 10. ProjectSnapshot持久化边界
ProjectSnapshot采用版本化Proto公开结构化数据契约，外层项目包可有清单、资源索引与校验信息。原始NASA DYN数据不强制嵌入项目包，优先保存来源标识、路径、版本、摘要及有效范围。
项目恢复不能依赖NASA服务永久可用；外部数据缺失时应明确unresolved或degraded，不伪造当前星历状态。缓存和资源再分发仍遵守许可约束。

## 11. ProjectSnapshot建议内容
| 分类 | 持久化字段 |
|---|---|
| 项目 | project_id、schema_version、created_at、updated_at |
| 场景 | ObjectId、ParentId、FrameId、可见性、通用状态 |
| 时间 | TimeInstant、PlaybackMode、rate、generation语义 |
| 参考系 | FrameId、父关系、提供者标识与来源 |
| 相机 | CameraId、FrameId、位置、姿态、投影、跟随目标 |
| 资源 | ResourceId、ResourceDescriptor、来源与校验摘要 |
| 扩展 | 插件标识、能力版本、声明式配置引用（不保存执行栈） |

created_at与updated_at属于墙上时钟元数据，必须与SimulationInstant区分，不能复用科学时间字段含义。

## 12. 项目恢复流程
1. 校验项目包版本、清单和权限。
2. 解析Proto持久状态并进行兼容性检查。
3. 建立新的Engine会话和内部代次句柄。
4. 恢复Time、Spatial、Scene的稳定逻辑状态。
5. 重新关联ResourceId、加载可用资源、恢复相机逻辑状态。
6. 检查插件提供者和外部数据来源是否可用。
7. 仅在科学状态修订一致时发布FrameSnapshot；资源缺失可标记PARTIAL，旧时间帧标记STALE，不能误报COMPLETE。
8. 恢复成功进入Ready；部分可用以恢复结果的degraded标识表达，暂不增加未经统一定义的Engine生命周期状态。
恢复过程中不得把外部项目包中的权限声明直接当成宿主授权。

## 13. 停机与清理顺序
建议Engine进入Stopping后：
1. 拒绝新写命令及新任务。
2. 停止仿真推进并固定最后一致快照。
3. 取消Simulation任务与宿主回调，拒收迟到结果。
4. 解除Scene对象的资源租约与订阅。
5. 释放Rendering GPU资源及设备适配。
6. 由Resources清理缓存与资源注册表。
7. 关闭协议事件流，发布终态信息，进入Stopped。
任何清理失败应结构化记录，不能因局部失败跳过剩余清理步骤。

## 14. 错误与恢复策略
初始化失败：不进入Ready，清理已分配资源。
时间跳转：旧generation结果不可覆盖新状态。
对象删除：内部句柄失效，旧拾取/任务结果拒收。
参考系失效：关联对象标记unresolved，Scene对象仍存在。
GPU设备丢失：Rendering/Resources恢复，不修改科学状态。
项目数据缺失：降级打开并标记不可用，不伪造星历。
不兼容Schema：明确拒绝或按批准的迁移策略处理，不静默丢字段。

## 16. 设计待定事项
- Detached对象重新挂载是否保留ObjectId。
- ProjectSnapshot中时钟播放状态恢复后是否自动继续运行。
- 部分资源缺失时Ready与Degraded状态如何表达。
- FrameSnapshot是否内嵌Scene或引用不可变共享数据。
- ProjectSnapshot是否支持增量保存与快照迁移。
- 插件声明式配置的权限与兼容策略。
这些留待第13阶段文档一致性审查时统一，不提前建立验证文档。

## 18. 第13阶段设计一致性澄清
ProjectSnapshot中的时钟generation不应直接复用旧会话的任务代次；恢复时建立新会话代次，并重新检查任务与资源引用。ProjectSnapshot与FrameSnapshot用途分离。资源缺失属于可用性状态，不自动将Engine标记Failed。Engine Paused不是生命周期状态。具体快照字段号仍由第09阶段统一设计。
