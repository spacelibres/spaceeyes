# VPS 自动部署与有限容量缓存设计

## 目标与环境

`www.spaceeyes.cn` 指向用户提供的 VPS。该机 Ubuntu x86-64、2 GiB 内存；用户要求按 20 GB 存储约束规划。已有 Caddy 负责 HTTPS，SSH 保持可用；用户要求停止的 PM2 已禁用。不得覆盖其他站点配置或在 VPS 编译 Rust/Bevy。

## 部署链路

GitHub Actions 在 main 推送后先执行项目完整检查，成功后使用同一提交构建 Linux Next standalone 与 WASM，打包后通过 HTTPS 向该域名的独立 webhook 发送。请求采用仅在 GitHub Actions secret 和服务器 root 专用配置中保存的共享随机密钥做 HMAC-SHA256，绑定提交 SHA 和完整包内容；接收端限制包大小、串行部署，并向 GitHub 查询 main HEAD，拒绝过期版本。服务端不持有 GitHub 写令牌。

部署服务将包写入临时目录、验证签名，再解包到独立版本目录；验证路径和包结构，安装共享缓存链接，启动并检查服务；成功后切换 current，失败回滚。保留最近两个版本，不修改用户其他服务或目录。Caddy 为网站和 webhook 配置独立域名路由；配置验证后平滑重载。

## 缓存与资源

服务器资源使用共享缓存，不写入 WASM 或版本目录，按需读取和获取；DYN 和静态源保留现有来源验证和覆盖语义。银河七级瓦片是已生成的固定共享资产，不在每次发布中重复传输或由 2 GiB 机器重新生成。缓存按目录设定软预算，删除较久未访问的可重建条目并保留近期写入和临时文件；留足系统、发布和紧急余量。缓存与操作系统合计以用户的 20 GB 为规划上限：固定银河约 1.3 GiB，动态/静态/转换缓存以约 6 GiB 为定期清理目标，保留两个发布包，系统总用量达到约 18 GiB 停止部署并收紧缓存目标。这不是内核硬配额，清理间隔内的突发写入或其他服务仍可能造成短暂超额，需监控告警。实际容量和清理过程必须量测，不能以降低显示质量代替。

## 安全、测试与边界

Webhook 仅允许 main、正确 HMAC、已成功的同次 CI、最新提交和受限大小的包；密钥不可提交或输出。测试签名拒绝、旧提交拒绝、包大小、部署失败回滚、缓存清理与受保护资源。先在本地和 CI 验证，再在 VPS 实测 HTTPS、静态资源、DYN 首次与缓存命中、部署、重启恢复及磁盘限制。GitHub Actions 和生产 GPU 等待真实结果，不用脚本通过代替现场验收。NASA 上游数据异常与科学精度保持独立的已知问题，不通过伪造数据解决。
