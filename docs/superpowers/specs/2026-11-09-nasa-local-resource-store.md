# NASA 资源本地化设计草案

## 目标与边界

将第一版 NASA Eyes 目录中已声明的贴图、模型依赖、恒星、银河及 DYN 原始数据准备并持久保存在服务器本地。一次准备完成后，浏览器仍按需向本地服务器请求，资源不进入 WASM；无需把全部文件同时加载进内存或 GPU。DYN 是按来源与时间覆盖分段的数据，离线可用不代表超出来源覆盖范围的数据存在，也不代表可以持续获得 NASA 的实时更新。

## 已核对的现状

- 原有行星贴图和银河瓦片有本地文件；模型及贴图的可再生缓存存在 3 GiB 清理限制，不适合作为永久资源库。恒星和 DYN 当前主要依赖内存缓存及上游请求。
- 本机参考目录 `C:/Users/stone/Documents/solarsystem/dynamo-cache/files` 有约 279 万个 DYN 文件、1126 个来源目录。当前 SpaceEyes 目录声明的 953 条 DYN 根路径均找到了 `def.dyn`；其中 901 条可直接严格解码，52 条需要结合现有来源版本审查及窗口策略复核，不能直接视为损坏或擅自修复。尚未证明全部子分段或时间覆盖完整。历史下载记录包含失败和 46 条待复核路径，须重新核验，不得据此标记全量完成。
- 当前受审查的模型与依赖清单合并去重后有 1373 个源地址，本机缓存原始文件均通过长度和 SHA-256 校验，共 724920263 字节；转换输出尚未全量确认。目录外未登记资源不得推断已经纳入。
- 使用现有 `fetchSolarDyn` 和解码器、以本机目录替代网络读取，在 TDB 847420778.1826147 成功回放地球、金星、火星、月球、木星、土星、ISS、LRO、BioSentinel、Juice、Europa Clipper，共读取 24 个原始文件。仅为单时刻代表性样本，不证明其他对象、姿态、历史范围或全部分段可用。

## 资源库与准备

1. 建立可配置、独立于源码构建产物的本地资源根目录；默认位于被 Git 忽略的工作目录。准备程序读取受审查的对象目录和资源清单，不接受插件传入任意上游地址或本地路径。
2. 分别准备：行星和卫星贴图、模型及其已登记依赖、恒星文件、银河资源，以及每个目录对象声明的全部位置和姿态 DYN 根、索引及对应子分段。资源来源、长度、SHA-256、数据版本、准备结果和失败原因形成可恢复的清单；DYN 另外记录可验证的时间覆盖、层级与缺口。
3. 优先复用用户已拥有的本地 DYN 原始文件，使用可配置的只读来源目录，避免立即复制数百万文件；缺失项通过独立准备/同步流程补齐并写入项目资源库。不得在原目录原地修改用户数据；如需获得可独立搬迁的副本，提供显式导出，而不是把本机绝对路径写入仓库。
4. 下载及导入使用有界并发、断点续传、临时文件与原子发布；固定资源按已登记 SHA-256 校验。DYN 来源未提供固定散列时记录实际散列与来源，不把本地计算出的散列冒充 NASA 签名；继续执行现有严格格式、时间覆盖及已审查异常窗口校验。
5. 对目标轨迹按实际来源覆盖逐层遍历 DYN 分段，核对原始引用与文件存在性；对第一版 1949-12-31 至 2049-12-31 的时间范围报告每个对象的实际覆盖与缺口。源本身不覆盖的时间不能下载或伪造。全量完成以清单逐项成功为准，禁止用根文件存在冒充所有分段完成。

## 运行与更新

- 服务端优先从经过核验的本地库读取，保持现有 NASA DYN 数据插件、SDK 和 Bevy 渲染边界。浏览器按原路径按需加载；不减少对象、动画、轨道长度或资源精度。
- 同步过程中，尚未准备的资源维持现有受控上游回退并持久保存成功结果；提供明确的严格离线模式，缺失或损坏时显示原因而不伪造数据。全量同步通过后，应能在断网状态下访问清单中实际覆盖的对象和时刻。
- 永久资源库不能沿用当前 3 GiB 自动清理策略；临时转换缓存仍可设置独立上限。更新由明确的同步操作产生可追踪的新快照，成功校验后原子切换；保留旧快照或失败恢复路径，不在播放时悄然覆盖正在使用的原始数据。来源有新数据时需显式同步，不能把旧快照描述为实时数据。
- 大规模资源准备需显示总量、字节数、状态和缺项；存储空间不足、网络错误、NASA 来源变化及格式错误均可恢复且明确报告。准备流程可暂停并重新运行，已有校验通过内容不重复下载。

## 实施与验收顺序

1. 为静态资源和恒星建立永久本地库及完整性/准备测试；验证同一资源离线加载、损坏识别和浏览器按需请求。
2. 为 DYN 增加原始分段持久库与可配置只读导入；验证同一对象、同一时间下来源散列、选择窗口、状态和轨迹与现有链路一致，并测试取消、缺失、过期快照及断网。
3. 提供可恢复的全目录同步和覆盖报告；实际复核现有约 279 万文件及历史缺项，补齐可获取数据。报告已完成、源不覆盖和下载失败，不把部分成功称为全量成功。
4. 在生产构建和真实 GPU 下验证地球、月球、ISS、火星、木星、土星及跨行星任务，覆盖指定时间范围内已有数据、快速切换与不同播放倍率；测量资源本地读取、CPU、内存、GPU/显存和长帧，无法取得的指标明确列出。断开上游后复测实际已同步项目及既有画质和功能。
5. 每个可独立验收的迭代更新受影响包的补丁版本和 CHANGELOG，执行适用完整检查，提交并推送当前分支，通过 `gh` 跟踪 CI；不可将未准备、未测试或远端未完成表述为通过。
