# SPACEEYES 项目文档与版本规范

版本：0.0.1｜状态：版本管理规则已批准｜日期：2026-10-27

## 强制规则
1. 全部受控代码、架构书、规则书、可行性方案书使用统一版本。规划期为0.0.0；首次正式开发已批准升级为0.0.1，此后严格按版本流程升级。
2. 经批准发布时只递增最小版本号；100进1：0.0.99→0.1.0，0.99.99→1.0.0。兼容性由SDK/Proto另行治理。
3. 每次代码变更必须同步更新根目录CHANGELOG.md，说明缘由、范围、验证证据、风险及提交关联；无记录不得合并。
4. 架构、对象模型、Proto、SDK、插件权限变化先更新对应MD及ADR；AI代码同样遵守。
5. 所有文档标记状态（规划/待审/批准）、版本、依据和变更历史；未经测试不得写“已验证”。
6. 原参考仓库solarsystem的0.2.73是独立项目历史，不得混作spaceeyes的版本。

## 核心技术纪律

2026-10-27用户新增强制交付规则：每次变更必须完整本地严格测试，并由GitHub CLI确认同一提交的GitHub Actions严格通过后才能交付到开发分支。先在development/verify-*分支创建候选提交供CI运行；通过gh run watch --exit-status及tools/verify_remote_ci.py核验核心/GPU和必需步骤成功后，只能以同一SHA fast-forward进入开发分支。开发分支推送后的CI也须核验后才能报告完成。未完成、失败、取消、跳过、缺项或SHA不符均不算通过；禁止直接推送未经远端验证的新提交。候选提交用于启动远端测试，不代表交付；任何后续文件修改或amend都重新验证。规则适用于文档、工具和实现变更，详见根AGENTS.md。
统一Rust核心、多编译目标；统一Next.js/React/TS界面；模块化、面向对象封装；Protobuf唯一公开结构化数据契约；首期NASA Eyes功能优先；最终AI按技能书自主生成插件。插件不得越权或修改核心私有代码。

## 变更控制
规划期记录在CHANGELOG的[Unreleased]中。首次受控发布须经项目负责人批准并同步所有受控成果。

## 版本升级强制流程（2026-10-27批准）
1. 统一版本是唯一发布版本；设计批准不自动升级。首次正式启动代码开发时由0.0.0统一升至0.0.1。
2. 每次正式版本更新仅对最小位+1；达到100时进位：0.0.99→0.1.0，0.99.99→1.0.0。不得跳号、擅自增加中间位或让不同受控成果采用不同版本。
3. 先明确变更范围及版本目标，再同步修改所有受控代码版本、文档版本、规则版本与项目版本标识，更新CHANGELOG.md，最后统一提交。
4. CHANGELOG.md必须记录升级前后版本、修改原因、影响模块、变更摘要、已进行或未进行的验证、已知风险及对应提交；没有记录的代码变更不得合并。
5. 如变更影响架构、对象、Proto、SDK、插件权限，先修订对应MD和ADR；已批准ADR的实质变更须另行批准。
6. 若发现版本不一致、CHANGELOG缺失或错误进位，应停止发布并先修复；不得用事后补记掩盖问题。
7. 当前为0.0.1。项目负责人已正式启动Rust核心工程开发。
