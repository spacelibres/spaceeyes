# 第一版规划与验收

状态：基于已确认方向的规划；具体对标样本与量化阈值需在实施前确定。日期：2026-10-28。

依据：[太空之眼平台架构书](太空之眼平台架构书.md)。第一版唯一体验对标为 NASA Eyes，使用太空之眼品牌。当前没有第一版业务实现通过验收的声明。

## 整体能力与依赖

第一版的目标是完成 NASA Eyes 基线下可浏览、可观察、可播放的体验。DYN 是数据入口，不是产品主线；任何子模块的完成都不能替代完整场景验收。

完整链路：选择天体 → 确定显示时间 → 按需获取目录、运动/姿态、模型和纹理 → 形成统一对象状态 → Bevy 展示 → 相机观察与时间播放 → 切换目标或退出并清理。

2026-10-31 用户确认的初始化例外：八大行星的轨道、姿态、高清表面与土星环在初始化阶段预载并驻留，界面显示实际准备进度；资源仍从服务器获取、不嵌入WASM。太阳保持程序化显示，月球与航天器资源继续按需。卫星远距点标记及名称不能因为模型不足一个像素就整体消失，仍须遵守有效性、遮挡和稳定碰撞规则。

| 能力 | 输入与依赖 | 主要责任 | 用户可见结果 |
|---|---|---|---|
| 对象浏览与选择 | 对象目录、标识、类型、父子及关联对象 | TS宿主与数据插件，SDK同步选择 | 能找到对象，信息面板与场景目标一致 |
| 时间与播放 | 明确时间尺度、有效覆盖、播放状态 | 平台定义统一状态，宿主提供操作，插件按时采样 | 暂停、倍速、跳时与返回当前时间语义一致 |
| 数据与资源获取 | 真实来源、对象/时间范围、缓存与请求策略 | TS数据源插件经受控入口获取 | 有加载、成功、缺数据和失败反馈 |
| 运动与姿态 | DYN样本及类型求值、父体和参考系 | 独立数据源插件标准化，经SDK提交 | 同一时刻位置和朝向可追溯，不伪造覆盖外状态 |
| 三维显示 | 标准化状态、模型、材质与贴图 | Rust/Bevy显示核心，优先复用现成能力 | 星体、光照、轨迹与标签达到对标要求 |
| 相机与尺度 | 选择目标、包围范围、FOV、局部原点 | Bevy核心执行相机，宿主通过SDK发出操作意图 | 聚焦、缩放、视角切换与跟随可用且稳定 |
| 面板与图层 | 选择状态、对象元数据、资源状态 | TS宿主及插件界面 | 对象信息、关联入口与图层开关一致 |
| 生命周期与预算 | 请求、订阅、资源和对象归属 | 插件管理其数据资源，核心管理显示资产 | 快速切换和退出不遗留任务或复活旧对象 |

依赖顺序不是“完整破解格式后再做全部显示”。先定义最小对象/时间/资源/相机协作契约，所需解码与显示围绕一个场景协同验证；未支持的类型和对象明确标出，再按下一场景增量补齐。

## 编码前的资源分析准入

先完成代表对象的资源地图、加载与解码链、更新/缓存、时间与参考系说明，并列出源码、样本和页面证据的缺口。参见[NASA Eyes资源地图与加载链路](NASA-Eyes资源地图与加载链路.md)。只有这些内容足以解释完整用户流程后，才进入详细实现设计与编码；不以已获取若干DYN文件替代完整分析。

## 首个贯通场景建议

采用“太阳系总览 → 选择地球 → 聚焦地球 → 查看并切换月球 → 时间暂停/播放/跳转 → 返回总览”的完整用户流程作为首个候选。该选择不是缩小平台长期天文范围，也不把所有行星一次纳入首个小成果。

地球和月球的完整目录、关联资源及姿态/运动覆盖必须先核对。目前仅有部分DYN端点、样本与页面观察证据，不能把整条数据链路视为已可用。若候选的数据不齐，记录缺口并评估是否补数据或调整代表对象，不用虚构轨迹充数。

这一场景同时检验目录、资源、数据插件、统一状态、SDK、Bevy、相机、面板、时间与清理。允许初始模型/贴图使用可替换的最小展示资源做接线验证，但它们不能冒充NASA真实数据或最终效果验收。

后续用火星检验表面与关联探测器，用木星检验卫星系统与标签，用土星检验环和取景。它们是场景驱动的扩展，不在初期分别建设互不贯通的子系统。

## 工作顺序

| 阶段 | 工作与产物 | 进入下一阶段的依据 |
|---|---|---|
| A 全局基线与对标 | 整体能力表、模块协作边界、代表场景、NASA Eyes截图与操作证据 | 用户流程和数据依赖可解释，未核验项明确 |
| B 最小场景详细设计 | 统一对象/时间/资源/相机契约，核对候选对象所需的目录、DYN、模型与贴图 | 所需数据范围、模块责任和验收条件齐备，不先铺开全格式/全资产支持 |
| C 最小端到端验证 | 按已确认设计，使TS数据插件经SDK驱动Bevy，完成候选场景 | 真数据、交互、播放、失败反馈及清理在同一流程中可验证 |
| D 按场景逐项扩展 | 补齐NASA Eyes基线中的星球显示、相机模式、轨迹/图层和资源效果 | 每次扩展都在完整用户流程中复测，未支持项可见 |
| E 集中验收 | 按批准环境、样本、视觉与数值阈值回归全部第一版范围 | 以下清单逐项有证据，执行适用于新项目的验证流程 |

先详细设计再实施。现有分析与格式研究作为证据输入，不自动增加产品范围，也不自动批准未确认接口。参考仓库和历史实现仅供学习，不能直接继承其测试命令、目录或架构约束。新项目的构建、测试与CI流程在开始实现前按实际技术栈设计确认。

## 验收清单

所有项目目前均未验收。每项记录环境、版本、步骤、预期、实际结果和证据；性能及科学误差阈值在实施前设定，不能失败后放宽。

- [ ] 效果：在同对象、同时间、可比视角下，对照天体/航天器、轨迹、光照和标签；有成对截图或录像。
- [ ] 相机：选择、聚焦、跟随、缩放、视角切换行为与批准的 NASA Eyes 操作记录一致，过渡不突跳、不失去目标。
- [ ] 时间：暂停、继续、改变播放速度、时间跳转及返回当前时间符合对标记录；不同帧率不改变同一时刻的数据状态。
- [ ] 数据：运行时按需请求真实 DYN，记录端点、版本、时间范围与来源；验证缓存命中、刷新策略和取消过期请求。
- [ ] 解码与求值：覆盖已声明支持的记录类型、边界与分段；损坏、未知版本、缺段、覆盖外和请求失败均明确反馈。
- [ ] 科学语义：单位、时间尺度、参考系、来源与有效范围可追溯，与适用参考结果按事先确定的容差比较。
- [ ] 显示精度：从近距离到远距离视角测试抖动、遮挡、深度与轨迹连续性；不以原始绝对坐标直接强转 f32。
- [ ] 插件边界：通过公开 SDK 操作，资源归属清晰；停用时处理请求、订阅、缓存与显示对象，不直接修改 Bevy 内部状态。
- [ ] 生命周期：页面缩放、离开、重新进入及资源加载失败后行为明确，不重复积累渲染实例或资源。
- [ ] 品牌：使用批准的 spacelibre VI，不照搬 NASA 标识或未经确认的资源。
- [ ] 集中验证：记录全部检查结果、实际提交 SHA 和 CI 状态，未结束或失败不能报告通过。

## 数据调取原则

先确认真实数据的可访问性、更新机制和使用条件，再决定浏览器直取或平台受控转发；转发不意味着启用 Nyx。按对象、时间与数据分段加载，不把每帧网络请求作为实时性的依据。缓存数据须注明范围与来源，不掩盖断网或过期状态。

## 后续范围

Nyx 服务器任务管理、更多计算工具（含 STK）、完整插件市场及大模型生成/安装插件另行规划。第一版的数据接口保留来源和扩展边界，不提前实现这些系统。
