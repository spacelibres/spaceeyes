# 银河与恒星七级 LOD 及物理渲染设计

日期：2026-10-31。状态：用户已确认整体实施；采用科学尺度，同一视场角与七级LOD同步，保留恒星源位置产生的视差。

依据：太空之眼平台架构书、NASA Eyes第一版基线；当前分支codex/bevy-planning，冻结分支不动。Rust/Bevy负责显示，TS数据插件与受控SDK提供资源。Nyx不参与背景显示。

## 本次目标

银河与恒星不再各自加载、各自切换。共用同一个相机、参考系和七级LOD状态，按需获取，平滑提升清晰度。采用线性HDR与PBR环境反射流程，保留银河暗带和星光的亮度层次，空白区域保持真正黑色。

这是太阳系及现有星空的显示升级，不扩展成没有数据支撑的完整三维银河漫游。

## 已核对的现状

- 银河目前为1024×512预览和4096×2048两档；宿主在ready后固定换高清，没有相机驱动的七级调度。
- 当前服务端已做Reinhard和sRGB转换，网页使用WebP；进入客户端HDR/色调映射链之前动态范围已经被压缩。
- stars.0至stars.5是六个源视星等分档，约-0.62至8.03；galaxies.0是1211个远处星系点，不能当作第七级恒星。合计43878点。
- 星点在启用后逐文件全部发布，目前没有与银河共用的LOD。渲染已有观察者位置与源坐标，但最低亮度及最小光斑会把本应不可见的点抬亮。
- 已有数据的543条距离/星等不一致保留审计，不为视觉效果修改原位置或伪造星表精度。

## 一、统一七级资源

NASA Deep Star Maps 2020官方提供去除前景亮星的银河HDR源：milkyway_2020_8k.exr，8192×4096。采用这份真实8K源生成金字塔，不把4K放大伪装成更高细节。

| 对外层级 | 内部索引 | 等距柱状全景分辨率 |
|---|---|---|
| 1 | 0 | 128×64 |
| 2 | 1 | 256×128 |
| 3 | 2 | 512×256 |
| 4 | 3 | 1024×512 |
| 5 | 4 | 2048×1024 |
| 6 | 5 | 4096×2048 |
| 7 | 6 | 8192×4096 |

- 服务器离线/资源准备阶段解码一次HDR源，生成线性HDR金字塔与瓦片、记录来源、尺寸、SHA256、格式和版本。不让第一个网页请求承担大EXR解码。
- 高层级采用256像素瓦片并带接缝边界；仅请求当前视锥所需瓦片和小范围安全边界。全景经度首尾连续、极区有专门采样测试。
- 默认使用Bevy支持的half-float线性HDR纹理容器；实施时先核验WebGL2真实采样能力，不静默退回已烘焙色调的LDR来声称HDR完成。
- 低级资源先可用；高级未就绪时保留父级，不黑屏、不出现未加载块。最高层只来自真实8K源，没有不存在的细节。
- 原始EXR不进入浏览器，更不进入WASM；网页只取所需派生资源。新增IBL/LUT资源同样外置并做WASM资产回归。

## 二、银河和star.bin同步

核心统一计算wantedLevel、readyLevel和过渡权重；输入包含视场角、视口物理像素密度、观察位置和资源就绪情况。采用滞回避免滚轮在分界处反复切换，目标层准备好后约0.15至0.3秒交叉淡入。

- 银河瓦片与恒星显示共用同一目标级别和过渡权重，不允许一边已到第7级、另一边还突然跳变。
- 六个恒星文件仍完整解析并保留源值。七档显示不等于七个文件：将源亮度分档组织为七个累积显示档，较暗星随观测需要淡入。加载优先级可使用源视星等，显示亮度继续由源绝对星等、观察距离和统一曝光求得。首版七档源视星等建议上限依次为6.00、6.40、6.80、7.25、7.58、7.82、8.03，属于显示档位而非七份新星表。
- galaxies.0维持独立星系点表示，接受同一LOD的负载与可见性调度，但不冒充恒星第7级，不生成不存在的星系贴图或体积。
- 同一ICRF/J2000方向映射只转换一次。相机旋转时两层同向投影；星点使用相机科学位置，银河远背景按方向采样。
- 普通滚轮接近行星主要改变相机位置，不强行拉伸银河。在太阳系尺度，银河及远星视差很小，这是用户已确认的科学尺度方案。
- 为实际星空放大提供一个受控“观测视场”调节，建议10°至100°。它修改同一相机投影，同时作用于银河、恒星与天体，触发同一LOD选择；不创建第二台星空相机，不改变星历或距离单位。
- 跨恒星观察若超出当前太阳系范围，不能继续用地球视星等文件顺序漏掉变亮的近星；需基于完整源位置重新筛选。现有全部源文件仅约1MiB，可采用全量核验缓存，仍受五万点预算约束。

## 三、物理渲染与黑位

银河是远处的辐射背景，不是被太阳照亮的金属或凹凸墙面。本次将PBR落实为可用的HDR辐射及环境反射，而非给天空贴一张虚构法线图。

1. 从NASA线性HDR源到GPU保留线性辐射值；客户端完成一次统一曝光和色调映射，去掉重复烘焙映射。
2. 银河本身按发射背景显示，不接受太阳直射着色；恒星光斑使用同一HDR空间与曝光规则。
3. 从同一HDR源准备低分辨率漫反射和预滤波镜面环境图，经Bevy的环境映射能力供PBR材质使用，反射强度独立有界。不能用全局环境光把宇宙背景和行星暗面整体抬灰。
4. 保留源银河尘埃暗带；本次没有三维尘埃密度数据，不制造虚假的体积遮挡、近距离银河墙或不真实的平移视差。
5. 原始零亮度保持零。黑位/曝光只用于清晰的显示映射，不把整个银河暗部一刀切死；用黑场与低亮度渐变测试兼顾深黑和暗部细节。
6. 恒星没有强制最低发光能量；点扩散光斑、Bloom阈值与亮度有上限，仅让足够亮的星形成小范围光晕，避免每颗暗星都铺出白雾。

## 四、架构和预算

- SDK技能书同步环境LOD资源、相机视场与状态字段，TS/Rust双重验证。资源仅引用宿主登记的清单与assetId，不开放任意URL、shader或Bevy内部对象。
- 环境依然只有一个所属会话；关闭/退出取消请求并释放专用GPU资源，旧请求不能复活图层。帧内切换使用就绪资源，不阻塞主线程。
- 星空合批，不一星一实体。银河GPU纹理初始硬预算64MiB，总背景预算目标96MiB；同时保留当前有效层与替换所需有限父级，超限先降低LOD而非撑爆GPU。
- 瓦片请求有界并发、重试和LRU；取消过时目标，失败保留父层。缓存、层级状态和错误可在诊断页查看。
- 保留聚焦30Hz/失焦5Hz及既有相机碰撞/惯性；未来VR每眼使用真实姿态与投影，共用资源缓存，不对头部姿态套鼠标阻尼。本次不宣称WebXR或VR已验收。

## 五、集中验收

- 七层资源尺寸、哈希、经度接缝、极区、HDR零值与动态范围；不允许用放大图充数。
- 同一FOV/观察姿态下银河和恒星方向一致；七级切换、滞回、交叉淡入、父级回退和关闭/重入无残留。
- 视场角与窗口/DPR变化使用一致像素密度；普通轨道移动不人为放大远背景。
- 黑场RGB为零、低亮度梯度无明显断层；星点与银河不重复叠加前景亮星，不靠最低光晕把黑位抬灰。
- 实际GPU检查太阳系总览、地球与土星近景、环境反射、透明环遮挡、视场缩放、连续旋转、7级加载和预算降级。
- 完整Rust/TS/WASM/资源/网页检查，补丁版本、CHANGELOG、提交推送当前分支，gh非阻塞核查CI。
