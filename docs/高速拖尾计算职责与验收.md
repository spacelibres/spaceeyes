# 高速拖尾计算职责与验收

本次修复以平台架构书和本地 NASA Eyes 的 `TrailComponent._updatePoints` 为依据：保留真实历史采样，增量补齐移动时间窗，拖尾前端连接当前科学位置。不通过缩短拖尾、隐藏卫星、降低资源精度或停止动画换取帧率。

实机地球总览与 ISS 近景显示，主线程同时承担 Bevy/WASM 渲染和整组航天器的自适应采样时，部分任务无法在真实采样覆盖失效前完成。两对象单元测试不能代表整组卫星。只调整队列、预算和缓冲不足以作为验收结论。

## 职责

- 主线程继续管理唯一仿真时间、相机、当前科学数据、对象生命周期和受控 SDK 发布。Bevy 核心继续负责显示、碰撞、遮挡和现有动画。
- 每个工作区一个固定分片计算池，Worker数量为 `max(1,min(4,floor(hardwareConcurrency/4)))`，只运行相同的 TS 科学求值与自适应采样代码。Worker 不加载 WASM，不创建渲染器，不自行请求网络，不直接使用平台 SDK 或操作 Bevy。
- 主线程把不可变的真实 DYN/ORI 数据及控制器选择、父体、参考系和姿态依赖元数据同步给 Worker。源首次出现或替换时同步增量，不能每帧复制完整星历。每个任务只传时刻、采样预算、相机观察信息和真实缓冲需求。
- 结果使用可转移的 Float64 缓冲；主线程核验工作区版本、选择、源版本、任务阶段、参考系和当前时间覆盖后，仍经原受控接口发布。过期结果不能覆盖当前场景。
- 初次仅把可由原生科学源独立求值的路径交给 Worker。已有私有历史源功能保留原实现；Worker 不可用或退出时保留原计算路径，不删除功能。

## 有界与一致性

队列受工作区 256 对象上限约束，同一对象不得积压多份请求。逻辑科学源继续限制100万条记录；线程复制另计，每线程最多100万条，池最多400万条记录副本。诊断必须区分实际记录数、估算数值载荷字节与真实堆内存，不能把数值字节当作整个内存占用。轨迹单对象最多 4096 输入点、会话最多 49152 点。可见窗口保留原点预算和误差阈值，真实前后缓冲分别采样，不抢占可见窗口预算。源缺口和不兼容分段不得连接。

相机观察必须带渲染时刻与实际取景参考体，不能把 100 毫秒前的相机位置和当前卫星位置混算。历史覆盖检查不得替换正式高精度采样缓存。姿态资源只使实际依赖它的科学采样失效。

时间跳转、选择、源替换、场景退出和取消必须撤销旧任务所有权；Worker 的输入、输出、失败恢复和释放均需验证。Worker 分批执行并处理新消息，主线程继续遵守 60fps 上限及已批准的超预算 30fps 调度；不自动降画质。

## 验收

1. 同一不可变科学快照在主线程与 Worker 得到相同位置、时刻、断点和样式语义；覆盖源替换、取消、Worker 失败和生命周期回归。
2. 执行完整 Rust、TS、WASM、发布构建、资源和原生渲染检查。
3. 用真实显卡验证固定起始时刻 `846972583.005967` 的地球系统、选中 ISS 近景、正反向加速、暂停/恢复和数据分段交界。记录倍率与观察参数，不以平均 FPS 或一张有轨道的截图替代验收。
4. 检查所有已发布航天器的当前头部及可见时间窗覆盖，记录真实数据不足的长历史目标，不能把它们伪装成完整覆盖。
5. 记录主线程耗时、显示间隔、队列、内存及控制台错误。GPU 时间或显存不可获得时明确注明。未实测的倍率和场景不宣称通过。

逐项实测结果写入本版本证据目录及 CHANGELOG，再提交、推送并通过 gh 跟踪 CI。
