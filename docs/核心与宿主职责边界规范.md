# 核心与宿主职责边界规范（Rust 唯一计算权威）

版本：0.0.1｜状态：受控规范（按项目负责人 2026-10-28 指令制定）｜日期：2026-10-28
上位文件：`docs/太空之眼平台架构书.md`、`docs/技术可行性方案书.md`
适用范围：全部 crates、adapters、apps、packages、插件与技能书；与本文冲突的历史表述，以本文为准。

## 1. 总则

1. **Rust 是唯一计算与状态权威。** 科学计算、数值算法、解码、时间尺度换算、星历求值、轨道传播、资源与渲染状态，全部由 Rust 编写并编译为 Native/WASM；核心行为的测试也必须在 Rust 中完成。
2. **TypeScript + Next.js 只负责交互与界面。** 浏览器宿主负责 DOM/React、输入、布局、可视化呈现、网络代理、WASM 生命周期和插件 UI 容器；不得持有第二套场景/时钟/科学状态，不得在 JS 中重算科学量。
3. **插件市场只分发交互与显示类扩展。** 面板、皮肤/主题、交互效果、快捷操作、模型工具入口属于插件范围；天文算法、数据解码、轨道/时间计算、场景写入权威不属于插件。
4. **原生能力不进市场。** 新的数据源、算法或核心能力通过 Rust crate + Proto 的版本化核心演进交付，由平台审核；不以 TypeScript 市场插件的形式绕过核心边界。
5. **公开结构化契约只使用 Proto。** Rust 生成 TS 类型；能力发现、SDK 技能书与实现同步；不得出现平行 Schema 或第二权威。

## 2. 职责划分

| 能力 | 归属 | 语言/位置 | 规则 |
|---|---|---|---|
| 场景对象、层级、事务、句柄 | Core | Rust `crates/scene` | 唯一写入口在 Engine；失败整批回滚 |
| 仿真时钟、倍速、步进、代次 | Core | Rust `crates/time` | 不读系统时钟；宿主只提供单调经过时间 |
| 时间尺度与历法（UTC/TAI/TT/TDB、闰秒、J2000） | Core | Rust（`crates/time` 或其受控子模块） | 显式尺度/历元；不得把标签当换算 |
| 参考系、变换、导数、覆盖区间 | Core | Rust `crates/spatial` | 不插值、不伪造缺失覆盖 |
| 任务调度、执行器、来源策略 | Core | Rust `crates/simulation`、`crates/engine` | 结果需 token/代次/时刻/来源校验 |
| 资源配额、上传、摘要、解码 | Core | Rust `crates/resources`、`crates/codecs/image` | 有界、可取消、失败不污染 |
| 图像/网格/DYN/协议字节解码 | Core | Rust | 解码与数值校验不得下放给 TS 或插件 |
| 轨道求值、星历求值、覆盖选择 | Core | Rust | 输入显式时刻与来源；越界显式报错 |
| 渲染、拾取、GPU 资源 | Core | Rust `crates/rendering` | 只消费一致快照；不驱动时钟 |
| 协议校验、命令/查询/事件映射 | Core | Rust `crates/protocol-adapter` | 幂等、原子、结构化错误 |
| 页面、布局、主题、皮肤、面板 | Host | TS `apps/web`、插件 UI | 只读核心投影；不写核心 |
| 输入、相机手势、时间控件交互 | Host | TS `apps/web` | 通过公开命令提交，不本地改写状态 |
| 数字/日期格式化与本地化 | Host | TS | 只格式化核心返回的显式值，不推导科学量 |
| 网络获取（DYN、纹理等） | Host | TS 代理 | 受权限/域名/大小/超时限制；字节交给 Rust |
| WASM 加载、画布、帧循环 | Host | TS | 一实例一宿主；卸载释放 |
| 插件清单、安装、授权、启停 | Host | TS `packages/plugin-host` | 最小权限、可撤销、失败回滚 |
| 市场目录、安装器、签名/锁文件 | Host/Service | TS | 精确版本、不可变制品、事务回滚 |

## 3. 数据流规范（以 DYN 为例）

1. 宿主/插件按权限从受控代理获取 DYN 字节（TS 只做网络与长度/超时管理）。
2. 字节通过 `resources.begin/append/finish_upload` 或等价的有界入口进入 Rust 核心。
3. Rust 完成格式校验、五类点解析、分段选择、求值与覆盖判断。
4. Rust 以显式时刻/来源/版本生成提供者样本或查询结果，经 Proto 返回。
5. 宿主只负责展示、格式化与把用户操作转换成下一条公开命令。

禁止路径：TS 解析 DYN、TS 计算轨道/姿态/时间差、TS 生成“科学”顶点、插件直接改 Scene/Clock、插件自带天文算法并冒充核心结果。

## 4. 插件市场范围

允许的贡献点：

- 面板/侧栏/属性编辑器等 UI 扩展；
- 皮肤、主题、配色、字体与视觉特效；
- 命令入口、工具栏、快捷操作（调用公开命令）；
- 展示型图层（由核心提供几何/数据，插件只做样式与交互）；
- 模型工具入口（参数校验、预览、确认由宿主/核心执行）。

禁止的贡献点：

- 在 JS 中解码 DYN/纹理/网格或实现星历/轨道/时间换算；
- 直接写 Scene/Clock/Resources 或绕过 Engine；
- 自带网络访问绕过宿主代理；
- 扩大自身权限、动态加载核心私有代码、修改市场审核规则。

数据源类插件若保留，只能承担“取字节 + 调用核心解码/求值”的适配职责；其计算部分必须位于 Rust。该类插件不进入面向第三方的 UI 插件市场，随核心版本发布。

## 5. 测试与验收规范

1. **核心行为必须有 Rust 测试**：单元、集成、GPU 像素回读、失败回滚、边界与溢出；不得以 TS 测试替代。
2. **TS 测试只覆盖**：UI 交互、线缆编解码、格式化、权限负向、浏览器用户路径；不得复制科学公式作为“验证”。
3. **跨语言互通用同一 Proto**：Native/WASM/TS 对同一请求逐字节或逐字段对照；合成边界值必须可重现。
4. **科学对照**：显式记录参考源（JPL Horizons/SPICE/官方 DYN）、时间尺度、参考系、单位与误差容限；没有对照不得宣称科学正确。
5. **性能证据**：核心热路径的性能测量在 Rust 侧完成；浏览器只报告端到端帧时间与资源占用。
6. **每次提交**：先失败用例，再实现；完整 `bash tools/check.sh --gpu` 通过后提交；文档、CHANGELOG、台账同步。

## 6. 与现状的差距及迁移项

| 现状 | 问题 | 迁移目标 |
|---|---|---|
| `packages/nasa-dynamo` 在 TS 中解析/求值/分段 | 科学计算位于宿主层，违反第 1/2 条 | 新增 Rust DYN 核心；TS 包降级为迁移期对照 oracle，运行时不再使用 |
| 浏览器 `solar-system.ts` 生成轨道管网格 | 科学几何在 TS 生成 | 由 Rust 计算轨道采样，经核心线图元/网格输出，TS 只提交与显示 |
| 浏览器时间轴按“相对秒”显示 | 无 UTC/TT/TDB 换算 | Rust 提供时间换算查询；TS 只格式化与输入 |
| 太阳系目录/半径/颜色在 TS 常量 | 领域数据分散在宿主 | 目录数据进入 Rust 受控表或版本化数据文件，经 Proto 查询 |
| 插件宿主同进程 | 非沙箱 | iframe/Worker + 权限清单；插件仍只做 UI |
