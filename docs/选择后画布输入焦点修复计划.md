# 选择后画布输入焦点修复

实机复现：总览鼠标点击太阳，信息面板自动把DOM焦点移到关闭按钮；鼠标保持(640,360)直接滚动，相机positionKm/desiredKm完全不变。Rust原生wheel依赖Window.focused与cursor_position，宿主控件焦点不应成为画布滚轮权限。

方案：复用workspace现有window capture wheel路由，在目标确为画布且运行有效时，使用passive:false捕获，preventDefault与stopImmediatePropagation后通过现有runtime.zoom/受控SDK发送一次缩放。保留HTML侧栏wheel隔离及原生滚动，不处理画布外其它控件；Rust原生输入保留给桌面与拖动，不让浏览器wheel双算。像素/行/页对应0.001/0.1/画布高×0.001，单次限制SDK[-1,1]。零值/非法值不发指令。

自动打开信息面板时，如果焦点已在画布，保留画布焦点；显式点目录/面板入口仍正常把焦点移到面板。不得靠每帧强制focus、鼠标晃动或放开所有Bevy焦点检查修复。

用单元测试验证单位、方向、上限、无效值、同事件只发送一次且下游监听器不重复；实机验证原地选中→立即滚轮、面板焦点下轮滚、正反缩放、按钮、拖动、面板滚动、目标切换与退出清理。完整全检、独立审查、web补丁、CHANGELOG、提交推送与gh CI。

画布wheel属于用户明确场景操作，因此同时focus画布（preventScroll），恢复渲染器正常焦点帧率；不会为了保持面板焦点而以未聚焦低帧率缩放。自动弹出面板仍不抢画布，显式点击面板仍可正常键盘导航，滚动面板不转移焦点。
