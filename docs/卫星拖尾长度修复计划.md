# 卫星拖尾长度修复

用户要求轨道线更长，沿用NASA Eyes拖尾及原有真实DYN边界。

根因：宿主2048点在密集场景平分后普通卫星仅约24点；数据层0.052弧度弯曲控制会将时间窗口压到约0.15圈，另有25%未来缓存占用。NASA TrailComponent以轨道动力学估算自动长度，并按约3度弯曲阈值采样。

执行：总会话输入点预算有界提升至16384，宿主总览/选中模式统一预留512点余量、普通对象最多160点、选中256点；保留逐帧最多一条维护和精度检查。未来缓存缩至1/16窗口；轨道源优先一周期，非轨道源以相对位置/速度的2π|r×v|/|v|²估算长度，不把全覆盖年代当轨道周期。保持30日上限、阶段/祖先覆盖交集、显式断点、过去裁剪和尾端渐隐；不把人造卫星强制闭合。

先验证160点的圆轨道能覆盖完整历史周期、未来缓存、预算替换与上限拒绝；保留急弯缩短/缺口断线和480倍时间测试。然后完整本地检查、独立审查和真实地球/ISS/MRO GPU回归，core/web递增补丁、CHANGELOG、提交推送并用gh跟踪CI。几何成本增加但保持明确上限，不能冒称所有轨道/设备性能认证完成。

性能补充：真实DYN五次测量中，160点ISS约10–13ms、MRO约5–11ms、Chandra约18–24ms（Node源求值，不是浏览器帧率）。所以未选中航天器首次拖尾改为每帧最多一条生成；有效窗口与相同预算复用，旧选中对象缩减时先释放容量。待处理集合只使用当前场景有效对象，图层关闭/返回/失效会移除待处理任务；无关轨迹生成失败只记录并清理该路径，不暂停科学时间。单路径4096点上限保留，总会话16384点。密集Earth回归同时检查首次生成和过期维护每帧最多一条。
