# NASA Eyes数据缓存与场景事务预算设计

全局路线第五批，用户授权连续实施。保持TS数据源插件所有权、DYN真实来源、Bevy受控显示与当前冻结边界。

当前retain清除显示状态却未清除decoded位置/姿态及dataParents；来源按完整epoch URL增长。改为活动场景缓存，不引入另一个全局缓存层：retain先验证唯一已登记ID且≤256，在修改或取消前拒绝非法集合。随后删除非活动的data/ori/dataParents/provenance，父体及姿态参考必须在活动依赖闭包内。保留现有真实有效覆盖内缓存复用。

已缓存decoded位置与姿态合计最多1,000,000条records，单文件现有100,000限制继续有效。替换按总量扣除旧项后计算，超过预算拒绝新数据，不能将活动依赖静默淘汰。该预算是记录上限，不能称精确JavaScript堆内存上限；在途最多4并发、文件16MiB、事务快照仍可能暂时额外持有旧场景，证据明确区分。测试可通过构造参数降低预算。

来源每对象每类型仅保留最近实际请求URL与hash/获取时间，至多512条；非活动删除。sha256异步完成后再次核验取消/场景世代，过期响应不得写入。兼容现有provenance(id)返回结构。

checkpoint回滚保持原场景数据与来源，但必须先取消当前在途请求、递增请求世代、清pending，然后只恢复快照数据，不恢复控制器或请求。闭包单次恢复；宿主成功事务显式释放快照引用，避免额外长期持有旧payload。失败回滚不使已取消请求重新写入。dispose全部清空。

验收轮换多个场景后旧数据/来源消失、总预算替换增减与原数据保留、同目标多epoch来源有界、hash/fetch跨retain及rollback不会污染、非法retain原状态不变、dispose归零；真实WASM快速选择/失败回退和浏览器代表场景复测。增加只读缓存计数供诊断，数值不得暗示精确堆大小。版本与完整检查/提交推送/gh照旧。
