# 高倍速播放稳定性修正

沿用已批准的 NASA Eyes 全项对齐及 60/30fps 帧预算方案，不降低画质、不关闭轨迹、不限制时间倍率。

## 本批有证据的修正

1. 本地 NASA `src/engine/core/BaseApp.js:140–148` 定义 UTC 1949-12-31 至 2049-12-31；`TimeManager-922.js` 在触界时暂停并置于边界内 1ms。本平台用现有 Hifitime 转换这两个日期，播放推进前检测越界；直接跳时越界明确拒绝，不发起无效数据请求。
2. 实测地球 10 hr/s：渲染 CPU p95 5.7ms、非关键任务 4 个，却因队列数大于 2 永远无法恢复 60fps。轨迹已分帧且耗时计入真实 CPU 成本；恢复判断改为 CPU p95 连续低于 8ms 达 10s，保留 2s 超预算降至 30fps与完整分辨率。队列数量继续上报，不代表耗时或 GPU 耗时。

## 独立待验证的问题

高倍速下缓存覆盖切换、跨帧采样过期与任务源变更可能仍引发停顿；不能仅凭本批通过就报告全部抖动已解决。保留真实资源缺失提示。GPU 毫秒若不可测明确缺项。

## 验证

先记录旧行为失败的 WASM 宿主边界测试与 Rust 恢复测试，再实施最小修复；执行现有全套检查与同场景浏览器诊断。不得用总帧数代替连续帧间隔验收。
