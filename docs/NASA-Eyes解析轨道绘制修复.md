# NASA Eyes 解析轨道绘制修复

## 本地源码对照与根因

参考 `C:/Users/stone/Documents/solarsystem/eyes/src/engine/components/OrbitLineComponent.js`。NASA 根据当前相对位置、速度和 DYN 引力参数恢复瞬时轨道，按 360 个一度区段绘制，并在对应区段加入当前天体位置。其完整轨道与 TrailComponent 的历史拖尾独立。

本平台之前虽然同样生成瞬时椭圆，却把完整轨道输出点数与全场景的 4096 科学采样点预算绑定。地球周围航天器较多时，月球只能分得二十多个点，因此显示为多边形。0.0.49 的历史拖尾修复不能解决这条完整轨道路径。

## 实现与平台边界

TS 数据源继续负责科学参数，使用已有当前相对位置、速度和引力参数计算半通径、轨道面正交基及偏心率分量。DYN orb 和目录直接声明的有界 orbitalElements 均使用同一路径；后者通过原控制器速度和 n²a³ 的等效引力参数展开。仅有界二体瞬时椭圆携带 `conic` 显示描述；历史、航天器拖尾、无界和退化状态不携带此参数。

现有受控 `visual.trajectory` 接口增加可选描述，不新增权限，不允许插件访问 Bevy 实体或任意 shader。SDK 复制冻结数组、拒绝未知字段；Rust 独立核验有限数、正半通径、单位正交基、偏心率小于一、至少两点、显式 orbit 类型及无断点。父体归属、对象所有权和生命周期继续使用原验证。

Bevy 侧按 `r = p / (1 + ec*cos(theta) + es*sin(theta))` 和轨道面基向量生成一度区段，首尾严格闭合；只在当前源位置仍落在该瞬时模型容差内时替换最近角度的顶点，防止陈旧模型被拉成假折线。科学位置、时间和轨道形状没有做美术平滑，二维投影呈椭圆是正常透视。

原 4096 科学采样点预算保持不变。解析展开另设核心实例最多 256 条的硬上限，每条 360 段，最多 92160 段；替换复用预算，清除和释放归还预算。缓存一度三角函数表，每个顶点每帧只求值一次。现有深度检测、距离渐隐和路径尺度控制继续生效。

这遵循 NASA 的完整轨道生成方法，不宣称已经移植其全部 LineMesh 抗锯齿、可变线宽或所有航天器任务控制器。
