# M3-1a 资源分层预算与统计实施计划

版本：0.0.1｜状态：本地验收与独立审查通过，远端按候选SHA核验｜日期：2026-10-27
依据：Resources规范第6节、ADR-004及M3有界资源入口路线；不改变资源唯一权威与Engine唯一写入原则。

目标：在大资源上传前先提供CPU资产、GPU容量与Staging临时缓冲的独立预算，公开可查询统计，保证GPU/临时资源不进入项目恢复数据。

## 契约

ResourceManager维护总额度及Cpu/Gpu/Staging三类额度，申请同时受类别与总额度约束。Engine原型采用总256MiB、CPU128MiB、GPU128MiB、Staging32MiB；它们是原型安全上限，不是性能或实际RSS/VRAM保证。宿主可通过Rust构造参数指定限制，恢复时采用目标宿主限制而非项目文件中的额度。旧ResourceBudget构造器保留总额语义，类别上限默认同总额。

纹理、网格与CPU加载声明归Cpu；浏览器Surface保守48MiB附件容量归Gpu；帧GPU分配及CPU打包/上传/回读暂存分别归Gpu与Staging。两类帧申请必须原子预留，失败不留部分占用；完成/错误后成对释放。租约及代次仍由原ResourceManager管理，清理使旧令牌无效。

ProjectState资源记录显式标记Cpu，只导出CPU资产或声明，恢复拒绝GPU/Staging记录；不保存GPU句柄或帧临时缓冲。Scene不得引用非CPU资源。query.resource_stats返回总量/分项占用、各上限及资源修订号；查询不推进时间、不消耗命令历史，Stop后占用归零。统计属于逻辑预留，暂不覆盖驱动内部开销、所有旧快照或宿主长期保留的输出副本。
