# 真实地球场景实施设计

2026-10-29，下一迭代详细设计；本文件不授权扩大第一版范围。依据架构书、第一版规划及DYN科学语义核对。当前0.0.6只完成数据结构准备，不声称实时运动科学链验收。

## 最小用户流程与范围

进入太阳局部场景→显示太阳原点与真实地球位置→选择/聚焦地球→暂停/播放/跳转→返回总览或退出。只取真实earth/sun/orb内联定义；不含月球、姿态贴图最终效果、Nyx、虚构轨迹、子段协议和完整太阳系。

太阳原点是此局部场景的坐标定义，不是声称太阳在宇宙惯性系静止。地球使用ICRF一致方向的日心相对位置；状态来源明确携带对象、父体sun、URL、响应内容散列、获取时间、DYN版本及算法版本。科学状态保持f64，显示层先减当前局部原点再缩放转f32；相机跟随不得回写科学坐标。

## 时间事实与不能绕过的接口条件

DYN记录ET数值按J2000秒解释与官方TDB端点位置达到米级一致，这是数据侧强证据。恢复应用TimeUtils以Unix减固定常数加闰秒计算，没有TT→TDB周期项，不能据此将其输出无条件标为严格TDB。

现有platform/state-contract.ts要求epochTdbSeconds、coverageTdbSeconds和frame='ICRF'。下一迭代不得直接把未核验ET重贴TDB标签来通过校验。最小方案先使用明确输入的TDB秒（例如来自本次官方Horizons指定JDTDB）和数据记录时间自变量进行求值；把映射假设、参考对照和误差作为数据适配器契约显式记录。UTC日期选择与“返回当前时间”在经过官方时间转换或经过独立验证的时间库实现前，不可宣称完整实现。若产品必须立即提供UTC当前时间，则严格UTC↔TDB转换是该项功能的真实前置条件；它不阻止先做明确TDB输入的接线实验。

覆盖来自真实首末记录[-3155716758.816,3155716869.184]，查询必须在范围内；不依据NASA网页配置日期截断数据，也不输出覆盖外伪有效位置。科学接口中的frame声明须限定为此earth来源与本轮独立对照支持的映射，不能推广所有对象。

## 模块责任与数据流

TS受控ResourceClient取白名单资源→decodeDyn解析/冻结记录→earth数据适配器核对inline orb与父体配置→二分选择相邻记录→按参考OrbPoint及OrbitalElements已证实算法求值→创建ObjectState→现有SDK/宿主端口→Bevy局部显示。

解析器无网络、无时间播放和无Bevy访问。适配器只允许body=0、非incremental；保留wxyz到显示引擎四元数类型的显式转换边界。本场景不提交姿态以免把未经外部对照的ori当成已验收方向。位置求值不能改成参数插值、Hermite或未经授权的新传播器。

播放以现有 Rust 统一时钟为唯一权威：宿主只把单调时钟测得的帧间隔传给 core.tick，再读取核心时刻给数据插件求值；暂停、倍率与跳时均经现有 SDK，不在 TS 另建独立锚点时钟。相同核心时刻、不同帧率必须产生同一科学状态。网络只随资源缺失/明确刷新变化，不按帧取数。切换目标、退出或改变来源时递增generation并取消过期请求；迟到响应不得复活旧对象。缓存命中仍记录来源散列与覆盖，不把断网/过期当实时成功。

状态明确区分loading、ready、unsupported、out-of-coverage、failed、canceled。ready只表明声明范围内可求值及显示，不表示科学精度通过；UI要能说明“NASA源数据展示实验/精度尚未验收”。不得把数据缺失替换为圆轨道或静止假对象。

## 下一迭代可执行验证与独立验收

1. 每次改动后运行 `node --test platform/tests/*.test.ts` 与 `platform/node_modules/.bin/tsc.cmd --noEmit -p platform/tsconfig.json`。固定第三方样本只在显式样本模式运行 `node --test platform/integration/dyn-samples.test.ts`，缺样本应失败。
2. 求值TDD：原始端点、段中点、首末边界、重复时间拒绝、覆盖外拒绝、wxyz旋转、body0、牛顿停止条件；比较已固定参考数值，同时保留独立官方对照结果，不能把二者混为一种测试。
3. 先用可执行参考实现复现上述两个段中误差；若不能复现，定位临时公式/记录选取误差后再决定实现。这个核对是开始生产求值代码的关键检查点。
4. 生命周期集成：延迟响应后取消、快速切换、缓存命中、HTTP失败、未知类型、退出清理；断言没有旧generation对象或多余请求。
5. Rust/TS/WASM全部适用检查与真实GPU截图：同历元同坐标；局部原点移动前后屏幕稳定；不同帧率相同t状态一致。接入渲染器后GPU缺项不能报告通过。
6. 独立验收项：正式UTC↔TDB转换、跨覆盖位置/速度误差阈值、参考系全域一致性、姿态和表面朝向、NASA Eyes配对视觉/相机体验、许可及远端CI。上述结果不得由本设计或解析器通过替代。

官方参数文档：https://ssd-api.jpl.nasa.gov/doc/horizons.html 。实施时参考固定源码提交4a8a83be2ff8298d7fe26fc5c9bbfe47f2fee7db；详细字段和公式见DYN科学语义核对.md。没有提交第三方rawDYN或本机网络配置。

## 固定源码实际执行复核（2026-10-29）

已在临时Node分析进程执行固定提交原始Pool、MathUtils、Vector3、Quaternion、OrbitalElements、OrbPoint、PointSet方法，未改求值方法正文；仅去掉模块import/export并以最小public-api命名空间装配，Interval仅提供构造字段，二进制reader使用对应LE读取。PointSet.load实际读取文件，PointSet.getPoints实际选择样本对，OrbPoint.calculate调用原始传播、旋转和lerp。没有把第三方源码写入本项目。

结果：index180选中时间[-118071584.24170244,-100434165.31018451]；index214选中[190336290,190866114]；index270选中[735606318,745226715]。原函数结果依次为(-144236921.98933175,-36646142.834800266,-15888843.962404052)、(-62538905.95417909,122209217.00807482,52981800.5822524)、(-74224918.54572031,-121103281.63269028,-52498177.478980795)。与前述独立临时公式复现之差仅浮点末位（小于1e-7 km）。因此字段、wrap、四元数、lerp比例和seek选择的临时复现错误已在这三点得到排除，两个段中大差值可由该固定恢复源码求值方法复现。

这个结论是“固定提交恢复源码方法与本样本/Horizons之间的可复现差异”，不是NASA当前官方网页运行时错误的断言。仍未核对官方线上是否使用相同代码、数据版本、控制器覆盖/时间偏移或上游生成策略，也未录制官方同历元画面/状态。下一迭代可以基于已复核的方法实现来源一致性，但科学精度必须独立说明；不能把恢复代码差异扩大解释为NASA系统整体缺陷。
