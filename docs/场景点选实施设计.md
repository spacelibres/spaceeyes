# 场景点选实施设计

日期：2026-10-30。依据平台架构书、第一版规划与验收及已批准路线中的场景操作阶段。

## 完整流程

用户在画布点选天体或已显示的标签，Rust 根据最近一次相机投影返回对象标识；宿主沿用目录选择的同一条流程，按需加载选中对象姿态和表面，通过 SDK 聚焦，目录选中状态与信息面板同步。点选空白保持原选择，拖动继续控制相机。

比较三种方式：TS 重新投影会复制核心坐标/相机状态；引入完整 Bevy picking 插件及事件 SDK 会扩大本批接口；由 Rust 发布只读投影命中帧、宿主查询并沿用既有选择流程，可以保持核心权威且验证完整用户流程。因此本批采用第三种方式。

## 边界

- Rust 负责真实对象投影、深度优先、远景标记命中范围与避让后标签矩形；球体采用屏幕投影圆盘，非模型三角形或土星环拾取。
- 内部宿主桥 `pick_object(u,v)` 接受画布内归一化坐标，拒绝非有限值或越界值。只返回候选标识，不自行修改时间、选择或科学状态；停渲染后不可拾取，候选还需核对当前对象有效性和显示失败状态。
- TS 只区分主指针按下/移动/释放：移动超过 6 CSS 像素永久判为拖动，离开、取消、多指操作不选中。无命中不请求资源；命中采用现有异步选择及旧结果隔离。输入来自 canvas 本身，面板事件不参与命中。
- 新接口只属于宿主，不加入插件上下文，不授予插件 Bevy 内部对象或额外权限。目录仍是键盘操作的等价入口。
- 光晕不算实体、轨迹不可点选；相近对象优先使用避让标签，不承诺任意尺度重叠对象都可直接命中。没有表面 LOD 或航天器精细拾取的完成声明。

## 实施与验证

1. `core/src/picking.rs` 定义投影命中帧，测试深度、标签、边界、无命中与清空；`renderer.rs` 在实际相机投影/标签布局完成后发布该帧；`wasm.rs` 暴露宿主查询并在停止后拒绝旧帧。
2. 网页手势辅助单独测试拖动、折返、取消、不同指针、非主键及正常点选；`solar-workspace.ts` 的 pick 沿用 select，真实 WASM 宿主流程验证没有命中不加载、有命中走同一选择链及退出后失效。
3. 画布调用宿主 pick，成功选中后展开信息面板；保持目录、图层与统一时钟已有流程。
4. 最终集中检查运行 Rust、TS、WASM、生产网页、原生相机和固定资源；真实 GPU 浏览器用鼠标点选可见标签/天体，验证空白及拖动不误选、目录同步、地球表面和返回总览；保留截图与缺项。
5. 按受影响包递增补丁版本、同步技能书和 CHANGELOG，提交推送当前分支，gh 非阻塞跟踪本次 CI。
