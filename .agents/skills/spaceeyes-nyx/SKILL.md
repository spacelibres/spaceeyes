# 太空之眼 Nyx 科学计算技能书

用于太空之眼服务器端 Rust 科学计算的规划、接入和验证。Nyx 是已确定的航天动力学首选，固定在服务器执行；Bevy 是浏览器显示端，两者不链接打包。第一版以 NASA Eyes 体验和 DYN 数据浏览播放为范围，Nyx 实现属于后续阶段。此技能由项目编写，不是 Nyx 官方技能，也不表示已完成库接入、数值认证或授权。

## 能力选择

| 任务 | 优先使用 | 边界 |
|---|---|---|
| 动力学、轨道传播、机动、任务分析 | Nyx（crate 名 `nyx-space`） | 按锁定版本逐项核实力模型、求解器和机动 API |
| 星历、天体状态、参考系与姿态转换 | ANISE | 核实内核格式、覆盖时间和所需转换，不能假设完整 SPICE 兼容 |
| 历元、持续时间和时间尺度 | Hifitime | 显式指定时间尺度，不把普通日期或渲染帧时间当科学时间 |
| 三维场景、资源、相机与绘制 | Bevy | 读取项目 Bevy 技能；显示坐标不能反向成为科学状态 |

## 工作流程

1. 读取项目架构书与 AGENTS.md。规划任务只输出能力、边界和待验证项，不创建业务实现或改变已确认选型。
2. 实施前核对锁定版本、对应源码、Cargo features、许可证与星历数据来源。当前来源快照见 [上游依据](references/sources.md)，它不是项目依赖锁文件。
3. 明确仿真目标、初始状态、中心天体、参考系、单位、历元与时间尺度、力模型、积分容差、终止条件和输出采样。缺少会改变物理含义的信息时先澄清，不默认为地球或 UTC。
4. 区分科学计算与显示。保留库所需数值精度；转换到 Bevy 前明确相对原点、比例、坐标轴与单位，不直接将天文绝对坐标强转为 f32。
5. 先完成最小有参考结果的科学算例，再扩大能力。验证要求见 [验证清单](references/validation.md)。
6. 报告实际版本、features、数据标识、参数、目标平台和验证结果；未完成项标明未验证。

## 平台边界

- TS 插件和大模型通过太空之眼公开 SDK 提交配置或读取结果，不获得 Nyx、ANISE 或 Bevy 内部可变对象。
- SDK、Proto 的详细设计尚未确认时，不自行创造接口并称为已批准规范。
- 禁止把所有科学功能预先塞入通用核心；Nyx 固定部署服务器，不进入浏览器 WASM，不改变 TS 插件技术方向。
- Nyx 的积分步长与误差控制由科学求解要求决定；输出采样、播放速度和渲染帧率分别处理。不能将 Bevy 每帧 delta 直接作为科学积分策略。
- 发生缺失星历、超出覆盖、参考系不匹配或积分失败时，返回明确失败及上下文。不要用零向量、旧轨迹或静默换模型伪装成功。

## 授权与运行条件

太空之眼原创代码采用 MIT；Nyx 等依赖保留自己的许可。Nyx 上游声明 AGPL，并有 premium 额外条款；ANISE/Hifitime 标注 MPL。不得推断关闭 premium、改用 WASM、拆成插件或服务就自动解决授权问题。将授权列为分发与正式接入检查，不擅自更改项目协议或联系第三方。

客户端经平台 SDK 提交计算配置，服务器校验并安排 Nyx 执行，提供状态查询、取消及结果读取。记录任务身份、输入、工具版本、数据与计算配置；页面断开不改变科学结果。服务器任务结果与 NASA DYN 数据是两条独立路径，DYN 不必经过 Nyx 重算。后续可扩展 STK 等工具，当前不实现。Nyx 无浏览器 WASM 验收目标；核验服务器算例、任务边界及客户端结果展示。

## 完整算例描述示例

月球附近航天器传播：明确初始位置与速度的单位、月心参考系及方向定义、带时间尺度的历元、所用星历覆盖、月球引力及所需摄动、误差容差、终止时刻和输出间隔。先与适用的参考轨迹比较，再转换为局部显示坐标交给 Bevy。求解、传输与显示分开计时和评估。
